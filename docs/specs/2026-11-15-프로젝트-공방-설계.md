# 「프로젝트 공방」 설계 (v0.21.0)

- 작성일: 2026-11-15 · 상태: 사용자 검토 대기
- 이 문서에서 **사용자가 고른 것**은 「(사용자)」, 나머지는 「(판단)」.

## 1. 의도와 왜

- **요청 (사용자):** 의상실·배지 말고 「지식 레벨링 보상」을 만들고 싶다. 방법으로, 배운 것을 바탕으로 **앱 안에서 작은 프로젝트**(간단한 게임이나 유틸리티)를 만들어 보게 한다.
- **왜:** 문제를 푸는 것을 넘어 「내가 배운 걸로 진짜 프로그램을 만들었다」는 경험이 보상이 된다. 배울수록 만들 수 있는 것이 늘어나 레벨이 오르는 느낌을 준다 (판단: 장을 끝내면 그 장까지의 문법으로 만들 수 있는 프로젝트가 열림).

## 2. 목표 · 하지 않을 것 · 실패로 볼 것

**목표**
- 프로젝트 5개 (사용자: A 대표작 5개).
- **단계별 안내형** (사용자: A). 한 프로젝트는 3~5단계. 단계마다 앱이 확인하고, 앞 단계 코드가 다음 단계로 이어져 하나의 프로그램이 자란다.
- 다 만들면 **완성작을 진짜 프로그램처럼 주고받으며 실행** (사용자: A). `input()`이 불리면 입력창이 뜨고, 답하면 이어진다.
- 완성작은 공방 **진열장**에 남아 언제든 다시 실행 (판단).

**하지 않을 것 (이번 판)**
- 자유 제작형(빈 편집기에서 처음부터) — 사용자 A안이 아님. 진열장의 완성작 코드를 고쳐 보는 「나만의 버전」도 이번엔 안 함.
- 그림·소리가 나오는 프로젝트(텃밭 같은 화면 그리기). 글자 입출력만.
- 바이트 보상 수치 — 미뤄 둔 바이트 경제 작업에서 정함. 이번엔 XP와 배지만.
- 장마다 1개(15개) — 반응을 본 뒤.

**실패로 볼 것 (시험이 통과해도)**
- 비전공 학습자가 단계 안내만 보고 막혀서 끝내지 못한다(단계가 너무 크거나, 그 장까지 안 배운 문법이 필요).
- 주고받기 실행에서 앞서 한 답이 사라지거나, 같은 판에서 무작위 결과가 바뀐다(숫자 맞히기의 답이 입력할 때마다 바뀜).
- 무한 반복(`while True`에 끝이 없음)이 앱을 멈추게 한다.
- 진행이 다른 기록(레슨·텃밭·경비실)을 덮어쓴다.
- 영어로 했을 때 단계 글·입력 안내가 한국어로 남는다.

## 3. 제약

- 엔진은 지금 Pyodide 작업자(`src/worker.js`, `src/py/runner.py`) 그대로. 격리(sealRealm)·CSP 그대로.
- GitHub Pages는 보안 머리글(COOP/COEP)을 정할 수 없고, 아이폰 사파리는 JSPI가 없다 → 실행을 진짜로 멈춰 기다리는 방법은 쓰지 않는다.
- 채점은 레슨 「직접 쓰기」 채점(`tests`의 stdin·expect, `require` 문법 검사)과 같은 방식.
- 콘텐츠는 데이터로 추가(코드 손대지 않고 프로젝트를 더할 수 있게). 첫 파일 상한(`build.py`) 안 — 프로젝트 본문은 장 파일처럼 따로 받는 파일.
- 저장 형식 `saveVer` 2 그대로, 새 칸 `projects`는 없으면 기본값(경비실 `guard`와 같은 방식).
- 화면에 넣는 데이터 글은 모두 `esc`. 앞서 고친 「떠날 때 묶음 떼기」(v0.20.1)를 처음부터 지킨다.

## 4. 만드는 방법 (사용자: 추천대로)

검토한 대안:
- **단계 확인:** **A (고름) 레슨 채점기 그대로** — 단계 = 「직접 쓰기」 문제(입력·기대 출력·필수 문법). B 단계별 전용 검사 코드(세밀하지만 새 장치 필요), C 완성작만 확인(단계마다 확인이라는 사용자 선택과 안 맞음).
- **주고받기 실행:** **멈췄다 다시 돌리기 (고름)** — 입력이 더 필요하면 실행을 끝내고 입력창을 띄움 → 답하면 지금까지의 답을 모두 넣어 처음부터 다시 실행. 진짜로 멈춰 기다리는 방법(보안 머리글·JSPI)은 §3 제약으로 불가.

### 4-1. 데이터 (`data/projects.js`, 영어 `i18n/en/data.json`의 `project.<id>.*`)

```js
{
  id: "P1", need: 3,                 // 열리는 장(그 장을 끝내면)
  title: "가위바위보", blurb: "...", // 진열장·목록 한 줄
  icon: "...",                       // 기존 아이콘 묶음 안에서
  intro: "...",                      // 리아의 시작 말
  steps: [                           // 3~5개
    { goal: "...", task: "...", starter: "...",   // starter는 첫 단계만. 이후 단계는 앞 단계 학습자 코드에서 시작
      tests: [{ stdin, expect, public }], require: [...], hints: [...], solution: "..." },
  ],
  play: { seed: true, prompt: "..." },  // 완성작 실행 안내(무작위를 쓰면 seed: true)
  finale: "...",                        // 완성 때 리아 말
}
```

- 단계 `solution`은 시험·검수용으로 빌드에서 빠진다(경비실 `solution`과 같음).
- 단계 채점은 그 단계의 `tests`만. 앞 단계 시험은 다시 보지 않는다(코드가 자라며 출력이 바뀌므로).

### 4-2. 프로젝트 5개 (판단, 사용자 승인한 대표작 방향)

| id | 열림 | 프로젝트 | 단계(대략) | 새 도구 |
|---|---|---|---|---|
| P1 | 3장 | 가위바위보 | 입력 받기 → 컴퓨터 선택 → 승패 판정 → 한 판 결과 출력 | `random.choice` (아래) |
| P2 | 5장 | 숫자 맞히기 | 답 정하기 → 한 번 맞히기 → 높다/낮다 → 반복 → 시도 수 | `random.randint` |
| P3 | 8장 | 단어장 퀴즈 | 단어 사전 → 문제 내기 → 채점 → 점수 | `random.choice` |
| P4 | 11장 | 할 일 목록 | 메뉴 → 추가 → 보기 → 파일에 저장·불러오기 | 없음 |
| P5 | 14장 | 날씨 카드 | JSON 읽기 → 도시 고르기 → 카드 모양 출력 | 없음 |

- **무작위(판단):** 레슨에서 `random`을 가르치지 않는다. 그래서 무작위가 필요한 단계에서 「새 도구 카드」로 `import random`과 그 단계에 필요한 함수 하나만 짧게 소개한다(레슨의 개념 카드와 같은 모양). 채점은 시험마다 무작위 씨앗을 고정해 기대 출력이 정해지게 한다.
- P4의 파일은 실행기의 가상 파일(레슨 11장과 같음). 완성작 실행 동안은 다시 돌리기마다 같은 입력으로 다시 쓰므로 한 판 안에서는 이어진다. 앱을 닫았다 열면 비어 있다(이번 판의 한계, 진열장 실행 안내에 한 줄).

### 4-3. 주고받기 실행 (`src/py/runner.py`, `src/pyrun.js`, 새 `src/ui/console.js`)

- 실행기에 「주고받기」 모드: `input()` 값이 다 떨어지면 지금 오류(InputMissing) 대신 **「입력 필요」 결과**(지금까지 출력 + 입력 안내 글)를 돌려준다.
- 화면(`console.js`)은 출력 아래 입력창을 띄우고, 답하면 지금까지의 답 목록에 더해 **처음부터 다시 실행**, 이전 출력과 같은 앞부분은 그대로 두고 새로 생긴 출력만 이어 붙인다.
- 한 판 동안 무작위 씨앗 고정(판 시작 때 정함, 「다시 하기」를 누르면 새 씨앗).
- 무한 반복·너무 긴 실행은 지금 실행 시간 제한·멈춤 장치를 그대로 쓴다. 다시 돌리기가 쌓여 느려지지 않게 한 판의 입력 수 상한(예: 50번, 넘으면 「한 판이 너무 길어요, 다시 하기」).
- 이 실행기 모드는 프로젝트 전용이 아니라 나중에 다른 곳에서도 쓸 수 있는 실행 방식으로 만든다(하지만 이번엔 공방에서만 씀).

### 4-4. 화면

- **입구 (판단):** 학습 길(홈)에 「프로젝트 공방」 카드. 3장 전에는 잠김 안내(「3장을 끝내면 첫 프로젝트가 열려요」).
- **공방 화면 (새 `src/ui/workshop.js`):** 프로젝트 5개 목록(열림·잠김·진행 중 n/m단계·완성) + 진열장(완성작 바로 실행).
- **프로젝트 화면:** 단계 머리(n/m, 목표 한 줄) + 리아 안내 + 레슨 「직접 쓰기」 화면(`mountWrite`)을 그대로 재사용. 통과하면 다음 단계로, 코드는 그대로 이어짐. 마지막 단계 통과 → 완성 창(리아 `finale`, XP) → 완성작 주고받기 실행.
- 단계 도중 나가도 그 단계 코드는 저장(레슨 이어 하기처럼).

### 4-5. 저장 (`save.projects`)

```js
projects: { v: 1, open: { P1: { step: 2, code: "..." } }, done: { P1: { at: "YYYY-MM-DD", code: "..." } } }
```
- `done.code`가 진열장에서 실행되는 완성작. 개발자 모드는 다른 칸(기존 규칙).

### 4-6. 보상 (판단)

- 단계 통과마다 XP 5, 완성 때 XP 20 (레슨 한 개와 비슷한 크기). 하루 목표·퀘스트 「XP 얻기」와 같은 길로.
- 배지 「첫 작품」(프로젝트 하나 완성), 「공방 장인」(5개 모두 완성).
- 바이트는 이번엔 주지 않음(바이트 경제 작업에서 정함).

## 5. 확인하는 법

- 프로젝트 데이터 검사(새 `tests/projects.py`): 각 단계 `solution`이 그 단계 시험을 통과, 앞 단계 `solution`이 다음 단계 시작이 됨, 그 장까지의 문법만(경비실과 같은 표, 새 도구 카드로 소개한 `random`만 예외), 오답 몇 개가 실패.
- 주고받기 실행 단위 시험: 입력 필요 → 답 → 다시 실행 → 출력 이어 붙이기, 같은 씨앗이면 같은 무작위, 입력 상한, 무한 반복 멈춤.
- 화면 흐름: 잠김 → 3장 끝 → P1 열림 → 단계 통과(정답 코드) → 완성 → 주고받기로 한 판 → 진열장에 남음, 나갔다 들어와도 단계 코드 유지, 영어, 개발자 모드.
- 대비(밝게·어둡게), `i18n_coverage`, 빌드 크기.
- 실기기(아이폰): P1을 끝까지 만들고 한 판 해 보기.

## 6. 만드는 사람에게 맡기는 것

- 각 프로젝트의 단계 나누기·글·시험·힌트(§4-2 방향, §5 검사 안에서).
- 공방 카드·목록·진열장의 모양(기존 토큰, 대비 통과).
- 주고받기 화면의 입력창 모양.

## 7. 검토에서 정한 것 (판단, 만드는 사람 검토 질문에 대한 답)

- **언어:** 프로젝트 글·시험·시작 코드·모범 답은 레슨처럼 **언어별로 따로**(한국어 `data/projects.js`, 영어 `data/projects.en.js` 또는 같은 파일의 en 칸 — 만드는 사람 선택). 출력 글이 언어마다 다르기 때문. 진행은 **시작한 언어에 묶임**: `open.P1.lang`을 저장하고, 다른 언어로 열면 「이 프로젝트는 한국어로 시작했어요 — 한국어로 바꾸면 이어서, 아니면 이 언어로 처음부터」를 고르게 한다(다른 언어 진행은 지우지 않음). 진열장의 완성작은 만든 언어 그대로 실행.
- **무작위 채점:** 채점 때는 실제 무작위를 쓰지 않는다. 시험에 `rand: [2, 1, ...]`를 적으면 실행기가 `random.randint`·`random.choice`가 그 값을 차례로 돌려주게 한다(`choice`는 그 값이 목록에 있으면 그 값). 그래서 파이썬 판(CPython·Pyodide)에 따라 달라지지 않고, 단계 글에 「무작위는 이 줄에서 한 번만」처럼 부르는 자리를 정해 준다. 완성작 실행에서만 진짜 무작위(한 판 씨앗 고정).
- **파일(P4·P5):** 단계·시험에 레슨처럼 `files`를 줄 수 있다(실행기 기존 기능). P4의 「불러오기」는 같은 실행(완성작 한 판) 안에서 앞서 저장한 것을 읽는다 — 다시 돌리기가 같은 입력으로 다시 쓰므로 이어짐. P5의 날씨 자료는 프로젝트 데이터의 가상 파일 `weather.json`. 완성작 실행의 파일은 앱을 닫으면 사라진다(저장하지 않음, 실행 안내에 한 줄).
- **코드 이어 가기:** 단계 글은 쓸 변수 이름을 정해 준다(「컴퓨터 선택은 `com`에 담아요」). 막히면 「정답 보기」 뒤에 **「모범 코드에서 이어 하기」**를 고를 수 있다(그 단계 모범 답으로 바꾸고 다음 단계로, 그 단계 XP는 없음). 다음 단계의 시작 코드는 학습자 코드.
- **P1과 3장 문법:** 3장까지 목록·모듈을 배우지 않는다. P1은 `random.randint(1, 3)`과 `if`로 가위·바위·보를 정한다. `import random`과 `random.randint`·`random.choice`만 「새 도구 카드」 예외로 검사 표에 더한다(프로젝트 검사에서만, 경비실 표는 그대로). P3의 `choice`는 8장이라 목록이 있다.
