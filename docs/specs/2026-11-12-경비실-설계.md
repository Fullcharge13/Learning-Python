## 1. 의도와 화면 흐름

**의도**: 배운 파이썬 문법으로 「막을 것은 막고, 들일 것은 들이는」 방어 코드를 직접 써 보며 보안 개념을 하나씩 익힌다. 파이는 텃밭 관리소의 문지기, 리아 교수가 사건을 맡기고, 크로우가 침입을 시도한다.

**입구**: 텃밭 화면 위쪽 「쪽지함」 옆 「경비실」 단추.
- 3장 평가(3-5) 통과 전: 자물쇠 + 「3장을 끝내면 열려요」.
- 새 사건이 열리고 아직 보지 않았으면 빨간 점(단추와 하단 「텃밭」 칸 모두, 기존 새 소식 점과 같은 방식).

**경비실 화면**(세로, 위에서 아래):
1. **머리**: 보안 등급 + 해결 수(n/6) + 「사건 목록」 단추.
2. **사건 카드**: 크로우 그림(포즈), 리아 교수 한마디, 상황, 보안 개념 한 줄 풀이, 꼬리표 「예방」 또는 「대응」.
3. **코드 칸**: 빈칸 모드(빈칸 누르면 보기 3~4개 고르기 창) / 직접 쓰기 모드(기존 CodeMirror 입력창). 직접 쓰기는 그 사건을 한 번 해결한 뒤 열린다.
4. **문과 시도 줄**: 「실행」 → 시도들이 차례로 문에 다가와 판정 표시. 재생 1배·2배·건너뛰기. 「움직임 줄이기」면 재생 없이 결과만.
5. **결과**: 「막은 공격 a/b · 들인 손님 c/d」. 시도 칸을 누르면 그 시도의 「왜?」 설명.

**판정 4가지**

| | 막음 | 들임 |
|---|---|---|
| 공격 | 🛡 막았어요 | ❌ 뚫렸어요 |
| 손님 | ⚠️ 잘못 막았어요(오탐) | ✅ 들였어요 |

- 모든 시도가 맞으면 **사건 해결**. 처음 해결이면 XP 5.
- 코드 오류: 기존 한국어(영어) 오류 안내 + 오류 줄 표시를 그대로 쓴다. 오류가 난 시도부터는 판정하지 않는다.

**사건 목록**: 열림·해결(✓)·잠김(「n장을 끝내면 열려요」). 해결한 사건은 다시 할 수 있다(XP는 다시 주지 않음).

## 2. 엔진

### 2-1. 파일

| 파일 | 하는 일 |
|---|---|
| `src/py/guard.py` (새) | 경비실 판정 규칙 전부. 일반 파이썬으로 `pytest`에서 바로 시험 가능 |
| `src/py/runner.py` | `run(..., guard=None)` 매개변수, `guard`가 있으면 `guard.py`의 `_guard_run(...)`을 부름 |
| `build.py`, `tools/dev.py`, `src/worker.js` | runner 글자 = `runner.py` + 줄바꿈 + `guard.py`(이어 붙임). **실행 파일은 지금처럼 한 개**(`py/runner-<지문>.py`), 서비스 작업자 목록 변경 없음. `strip_runner`는 이어 붙인 결과에 적용 |
| `tests/py/conftest.py` | 시험에서는 `runner.py`가 `guard.py`를 일반 import로 찾는다(이어 붙인 실행에서는 이미 같은 이름공간에 있음 — `runner.py`는 `_guard_run`이 없을 때만 import) |

### 2-2. 코드 속 이름(한·영 공통)

명령·변수 이름은 언어와 상관없이 영어 하나로 쓴다(텃밭의 `move`·`harvest`와 같음). 시도 값·안내 글만 언어에 따라 바뀐다.

| 이름 | 쓰는 방식 | 뜻 |
|---|---|---|
| `attempt` | script | 지금 시도 값(엔진이 실행 전역에 넣음) |
| `password` | script·loop (G1·G4) | 진짜 암호 값(사건 데이터가 주면 넣음) |
| `block()` · `allow()` | script·loop | 지금 시도를 막기 · 들이기 |
| `has_try()` | loop | 남은 시도가 있으면 `True` |
| `next_try()` | loop | 다음 시도 값을 꺼내고 그 시도를 「지금 시도」로 삼음 |
| `check(...)` | func | 학습자가 만드는 함수. `True` = 들임, `False` = 막음 |

### 2-3. 세 방식

| 방식 | 장 | 실행 | 판정 |
|---|---|---|---|
| `script` | 3 | 시도마다 학습자 코드를 **새 이름공간에서** 한 번씩 실행(`attempt`만 바꿔서) | 그 실행에서 부른 `block()`/`allow()`. **아무것도 안 부르면 `none` = 들임**(막는 걸 잊으면 뚫린다) |
| `loop` | 5 | 학습자 코드를 한 번 실행. 학습자가 `next_try()`로 시도를 꺼냄 | 꺼낸 시도마다 그 뒤 부른 `block()`/`allow()`. 판정 없이 다음을 꺼내거나 실행이 끝나면 `none` = 들임. **끝까지 꺼내지 않은 시도도 `none` = 들임** |
| `func` | 4·6 | 학습자 코드를 한 번 실행(정의) → 시도마다 `check(attempt)` 호출 | 돌려준 값이 `True`면 들임, `False`면 막음. 그 밖(`None` 포함)은 오류 `GuardAnswerError`(「check는 True나 False를 돌려줘야 해요」) |

공통 규칙:
- 한 시도에 `block()`/`allow()`를 두 번째로 부르면 무시하고 사건 `twice`를 남긴다(첫 판정 유지).
- `func` 방식에서 `block()`/`allow()`·`next_try()`를 부르면 `GuardUsageError`(「이 사건에서는 check가 True/False를 돌려줘요」). `script`에서 `next_try()`를 불러도 같은 종류의 오류.
- 시도가 없는데 `next_try()`: `GuardUsageError`(「더 이상 시도가 없어요 — has_try()로 먼저 확인해요」).
- 시도는 사건당 20개까지(데이터 시험으로 보장, 엔진도 20개 넘게 받으면 앞 20개만).
- 시간 제한은 기존 3초(전체 실행 기준). `while True:`로 시도를 꺼내지 않고 도는 코드는 기존 시간 초과 처리.
- 같은 코드·같은 시도 → 같은 결과(무작위 없음).
- 안내 글은 `lang`("ko"|"en")에 따라 runner의 기존 번역 표(`_tr_for`)에 넣는다.

### 2-4. 주고받는 모양

```
run(code, stdin, require, guard={
  mode: "script" | "loop" | "func",
  tries: [{ value: str|int, expect: "block" | "allow" }, …],   // 1~20개
  password?: str,
  lang: "ko" | "en" })

result.guard = {
  events: [{ i, verdict: "block"|"allow"|"none", ok: bool, twice?: true }],   // 판정한 시도만, 순서대로
  stats:  { attacks_blocked, attacks_total, guests_allowed, guests_total },
  solved: bool,          // 모든 시도 ok 이고 오류 없음
  stopped: null | "error" }
// 오류는 기존 result.error(줄 번호·종류·한국어/영어 안내) 그대로. events에는 오류 전까지만.
```

- `ok` = (`expect`가 block이고 verdict가 block) 또는 (`expect`가 allow이고 verdict가 allow 또는 none).
- 결과 대조(텃밭 C62와 같은 안전장치): 앱은 `stats`·`solved`를 `events`와 `tries`로 다시 계산해 다르면 결과를 버리고 「실행 결과를 확인하지 못했어요」.

## 3. 사건 (데이터 `data/guard.js`)

### 3-1. 데이터 모양

```
INCIDENTS = [{
  id: "G1", need: 3, mode: "script", tag: "respond" | "prevent",
  concept: "인증", title, brief, ria,               // 화면 글(영어는 i18n/en/data.json의 guard.* 열쇠)
  crow: { intro: "wave", lose: "cry" },              // 포즈 이름
  password?: "sunflower77",
  start: "if attempt {0} \"sunflower77\":\n    {1}\nelse:\n    {2}\n",   // {n} = 빈칸 n
  blanks: [{ options: ["==", "!=", "="], answer: 0 }, …],
  solution: "…",                                      // 정답 코드(시험용, 화면에는 안 보임)
  tries: [{ value, expect, why }, …],                 // why: 「왜?」 설명
}]
```

- 시도 값은 한·영 모두 같은 값을 쓴다(암호·숫자라서 번역할 것이 없음). `why`와 화면 글만 번역.

### 3-2. 첫 판 사건 6개

각 사건의 `solution`은 **그 장까지 배운 문법만** 쓴다(§6 시험이 검사). 1~6장 레슨에 `isdigit()`이 없으므로 G6은 `ch in "0123456789"`를 쓴다. `len()`은 4장부터 쓴다.

| id | 장 | 방식 | 꼬리표 | 제목 | 개념 |
|---|---|---|---|---|---|
| G1 | 3 | script | 대응 | 창고 문 암호 | 인증: 확인된 사람만 들이기 |
| G2 | 3 | script | 대응 | 한밤중의 손님 | 접근 통제: 정해진 때만 들이기 |
| G3 | 4 | func | 예방 | 뻔한 비밀번호 거르기 | 추측하기 쉬운 비밀번호 |
| G4 | 5 | loop | 대응 | 밤새 두드리는 크로우 | 무차별 대입 → 계정 잠금 |
| G5 | 5 | loop | 대응 | 쏟아지는 장터 주문 | 요청 수 제한(서비스 거부 공격 완화) |
| G6 | 6 | func | 예방 | 새 계정 비밀번호 검사 | 비밀번호 강도 |

**G1 창고 문 암호** — `password = "sunflower77"`
```python
if attempt == password:
    allow()
else:
    block()
```
시도: ✅`sunflower77` · 🛡`Sunflower77`(대문자 하나도 다르면 다른 암호) · 🛡`sunflower 77` · 🛡`123456` · ✅`sunflower77` · 🛡`password` · 🛡`""`(빈 값)
빈칸: `==`(보기 `==` `!=` `=`) · `allow()`(보기 `allow()` `block()` — 들이는 칸은 판정 명령을 안 부르는 보기가 `none` = 들임으로 정답과 같아지므로 두 개만) · `block()`(보기 `block()` `allow()` `print("막아요")` — 출력만 하고 막지 않으면 공격이 뚫림)

**G2 한밤중의 손님** — `attempt`는 출입 시각(0~23, 정수)
```python
if attempt >= 9 and attempt < 18:
    allow()
else:
    block()
```
시도: 🛡`3` · ✅`9`(경계: 9시 정각은 들임) · ✅`14` · ✅`17` · 🛡`18`(경계: 18시는 문 닫음) · 🛡`23` · ✅`12` · 🛡`0`
빈칸: `>=`(보기 `>=` `>` `<=`) · `and`(보기 `and` `or`) · `<`(보기 `<` `<=`)

**G3 뻔한 비밀번호 거르기**
```python
def check(attempt):
    if attempt == "0000" or attempt == "1234" or attempt == "1111":
        return False
    return True
```
시도: ✅`4821` · 🛡`0000` · 🛡`1234` · ✅`7305` · 🛡`1111` · ✅`9064`
빈칸: `or`(보기 `or` `and`) · `return False`(보기 `return False` `return True` `print(False)`) · `return True`(보기 `return True` `return False` `pass`)

**G4 밤새 두드리는 크로우** — `password = "sunflower77"`. 틀린 시도가 3번 쌓이면 그 뒤로는 맞는 암호라도 막는다(잠금).
```python
fails = 0
while has_try():
    attempt = next_try()
    if fails >= 3:
        block()
    elif attempt == password:
        allow()
    else:
        block()
        fails = fails + 1
```
시도(순서대로): ✅`sunflower77`(손님) · 🛡`sunflowr77`(손님 오타, 틀림 1) · ✅`sunflower77`(손님) · 🛡`123456`(크로우, 틀림 2) · 🛡`password`(틀림 3 → 잠김) · 🛡`sunflower77`(**잠긴 바로 뒤라 맞아도 막음** — 크로우가 맞혔을 수 있음. 잠금 직후에 두어야 `> 3` 보기가 실패함) · 🛡`qwerty` · 🛡`letmein`
빈칸: `has_try()`(보기 `has_try()` `True` `fails < 3`) · `>= 3`(보기 `>= 3` `> 3` `== 0`) · `fails = fails + 1`(보기 `fails = fails + 1` `fails = 0` `break`)

**G5 쏟아지는 장터 주문** — 들인 수를 세어 5개까지만.
```python
count = 0
while has_try():
    next_try()
    if count < 5:
        allow()
        count = count + 1
    else:
        block()
```
시도: 주문 번호 `"주문 1"`…`"주문 10"`(영어 `"order 1"`…, 값만 다름) — 1~5 ✅, 6~10 🛡
빈칸: `count < 5`(보기 `count < 5` `count <= 5` `count > 5`) · `count = count + 1`(보기 `count = count + 1` `count = 5` `pass`)

**G6 새 계정 비밀번호 검사** — 8자 이상, 숫자 하나 이상, `pie`(대소문자 무관)가 들어가면 안 됨.
```python
def check(attempt):
    if len(attempt) < 8:
        return False
    if "pie" in attempt.lower():
        return False
    has_num = False
    for ch in attempt:
        if ch in "0123456789":
            has_num = True
    return has_num
```
시도: ✅`sunflower77` · 🛡`a1b2`(짧음) · 🛡`abcdefgh`(숫자 없음) · 🛡`PIE2026xx`(이름 포함) · ✅`carrot2026` · 🛡`pie12345` · ✅`potato99garden`
빈칸: `< 8`(보기 `< 8` `> 8` `== 8`) · `.lower()`(보기 `.lower()` `.upper()` 빈 글자) · `has_num = True`(보기 `has_num = True` `has_num = False` `break` — `return True`는 시도 7개에서 정답과 같은 결과라 보기에서 뺌)

- 빈칸의 오답 보기는 **하나씩 넣었을 때 반드시 해결에 실패**해야 한다(§6). 실패하지 않는 보기가 나오면 보기를 바꾼다(구현 중 판정 기록).
- 오답 `print("막아요")`(G1)처럼 판정 명령을 안 부르는 보기는 `none` = 들임이 되어 공격이 뚫린다 — 의도된 가르침. 반대로 **들이는 칸**에서는 판정 명령을 안 부르는 보기가 정답과 같아지므로 쓰지 않는다.

### 3-3. 크로우 대사·리아 교수 한마디

사건마다 등장 한 줄(크로우), 해결 한 줄(크로우 패배), 리아 교수 의뢰 한 줄. 데이터 `data/guard.js`에 두고 영어는 `i18n/en/data.json`. 말투는 기존 대사 표(`data/lines.js`) 수준의 짧은 존댓말(리아)·반말 장난(크로우).

## 4. 크로우 그림

- 원본 시트 `art/crow_sheet.svg`(Claude가 사용자 그림을 보고 다시 그림) → `tools/crow_import.py` → `data/crow.js`(리아 교수 `ria_set2_import.py`와 같은 길).
- 첫 판 6포즈: `wave`(등장, 손 흔들기) · `wait`(둥지에서 웅크림) · `shock`(🛡 막힘, 깜짝) · `loot`(❌ 뚫림, 보석·사과 뜯기) · `cry`(해결, 비 맞으며 울기) · `rank`(등급 화면, 날개 펼친 「세계 정복」 자세).
- 생김새(사용자 그림 기준): 짙은 남보라 몸, 보라 뿔 두 개, 노란 부리, 빨강/노랑 눈, 끝이 화살 모양인 꼬리, 박쥐 날개 느낌. 몸통·뿔·꼬리는 공유하고 눈·부리·날개·소품만 포즈마다 바꾼다.
- **그림 안에 글자 없음**(`<text>` 금지). 말풍선은 앱이 언어에 맞게 띄운다. 머리띠의 「정복」 글자는 무늬로 바꾼다(정찰 포즈는 첫 판에 없음).
- 크기: `data/crow.js` 15KB 이하(빌드 시험). 첫 파일 상한 820KB 안.
- **외모 승인**: 구현 첫 작업에서 6포즈 시안 시트(PNG, `docs/img/crow-sheet.png`)를 보여 주고 사용자 승인 뒤 다음 작업으로. 승인 전에는 화면 연결 작업을 하지 않는다.
- 나중 판 후보 컷: 정찰(돋보기), 연기 비행, 분노, 환호, 폭탄 선물 상자(악성 첨부·트로이 목마).

## 5. 저장·보상

**저장** `save.guard`(텃밭 `save.garden`과 따로):
```
{ v: 1,
  solved: { G1: { firstTry: bool, how: "blank" | "code" }, … },
  code:   { G1: "직접 쓰기 마지막 코드" },
  blanks: { G1: [고른 보기 번호 | null, …] },
  seen:   ["G1", …],
  runs:   0 }
```
- `saveVer` 그대로 2. 옛 저장에 `guard`가 없거나 모양이 깨졌으면 기본값으로 채운다(알 수 없는 사건 id는 버림).
- `firstTry`: 그 사건의 첫 실행에서 오류 없이 해결했는지(빈칸·직접 쓰기 상관없음).

**보상**
- 사건 첫 해결: XP 5(한 사건에 한 번). 바이트 없음. XP는 기존 하루 목표·연속 기록에 들어간다. 6개 합 30 XP.
- 배지 2개(`data/badges.js`, 15 → 17개): `guard_first` 「첫 방어」(사건 하나 해결) · `guard_perfect` 「완벽한 문지기」(6개 모두 `firstTry`).
- 보안 등급(저장 안 함, 해결 수로 계산): 0~1 견습 문지기 · 2~3 문지기 · 4~5 경비 반장 · 6 텃밭 보안관.
- 경제 시뮬레이션(`tests/sim/economy.js`)은 바이트를 바꾸지 않으므로 결과가 같아야 한다.
