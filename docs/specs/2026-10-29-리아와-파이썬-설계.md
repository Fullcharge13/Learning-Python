## 1. 목적

비전공자가 아이폰으로 하루 5~10분씩 리아 교수와 Python 기초(출력, 변수, 조건문)를 익히고, 레슨마다 직접 코드를 써서 실행해 본다.

**v0.1에서 확인할 것**: 「이 흐름이 재미있어서 내일도 켜고 싶은가」.

**성공 기준**
- 처음 온 사람이 설명 없이 첫 레슨을 끝내고, 첫 직접 작성 문제를 실행해 결과를 본다.
- 1~3장 15개 레슨 모두 자동 점검(`tests/content.py`)을 통과한다.
- 아이폰 크기 화면 8개에서 넘침·오류가 0건이다(`tests/flow.py`, Chromium + `iPhone 17` 기기 설정).
- 가상 학습자 30일 시뮬레이션에서 첫 의상 구매까지 3~4일이 걸린다.

**v0.1에서 하지 않는 것**: 서버, 로그인, AI 튜터 대화, 주간 리그, 어드벤처, 4장 이후 내용, 데스크톱 전용 배치(PC에서도 열리지만 휴대폰 폭 그대로 가운데에 놓는다).

## 4. 레슨 데이터와 채점

### 4-1. 레슨 표 형식

```js
{ id: "2-1", chapter: 2, title: "변수는 이름표", goal: "값에 이름을 붙여 다시 쓸 수 있다",
  summary: ["변수는 값에 붙이는 이름표", "= 는 오른쪽 값을 왼쪽 이름에 넣기", "다시 넣으면 새 값으로 바뀜"],
  cards: [ { say: "변수는 상자에 붙이는 이름표예요.", code: "coffee = 4500\nprint(coffee)", out: "4500" } ],
  items: [
    { type: "choice", concept: "assign", q: "출력은?", code: "a = 3\na = 5\nprint(a)", options: ["3","5","8"], answer: 1 },
    { type: "blank",  concept: "assign", code: "name = ___", chips: ["\"리아\"", "리아", "=리아"], answer: 0 },
    { type: "order",  concept: "print",  lines: ["price = 4500", "count = 2", "print(price * count)"], expect: "9000" },
    { type: "write",  concept: "expr",   task: "…", starter: "", tests: [ { stdin: "", expect: "14000", public: true } ],
      require: [], hints: ["재확인", "개념", "방향", "뼈대"], solution: "…", explain: "…" },
    { type: "check",  concept: "assign", q: "이해도 확인 질문", options: [...], answer: 0 }
  ] }
```

- `concept`는 취약 개념 집계에 쓴다.
- `require`는 코드 구조 조건이다(예: `["If"]`는 if 문이 있어야 함). Python 내장 `ast`로 검사한다.

### 4-2. 터치 문제

| 형태 | 조작 | 채점 |
|---|---|---|
| 객관식 / 이해도 확인 | 보기 터치 | 번호 비교 |
| 빈칸 | 낱말 칩 터치 (화면 키보드 쓰지 않음) | 칩 번호 비교 |
| 순서 맞추기 | 줄 블록을 차례로 터치, 다시 누르면 빼기 | 정답 순서와 비교. 순서 문제는 정답 순서가 정확히 하나라서(실행 기록 C23) 실행 결과 비교와 같다 |

틀린 문제는 레슨 끝에 한 번 더 나온다. 다시 맞히면 레슨 완료로 친다.

### 4-3. 직접 작성 채점

- Pyodide는 Web Worker(화면 뒤에서 따로 도는 일꾼) 안에서 실행한다. 화면은 멈추지 않는다.
- 한 번 실행의 제한 시간은 **3초**다. 넘으면 작업자를 끝내고 새로 띄운 뒤 「시간 초과」를 알린다.
- `input()`은 시험의 `stdin` 값을 차례로 넣는다. 값이 모자라면 「입력이 더 필요해요」로 알린다.
- 출력은 각 줄 끝 공백과 마지막 줄바꿈 차이를 무시하고 비교한다.
- `input()`이 있는 문제는 시험 2~4개, 없는 문제는 공개 시험 1개를 둔다(실행 기록 C20). 공개 시험 1개는 기대 출력을 보여 주고, 나머지(숨은 시험)는 통과 여부와 「어떤 경우에서 틀렸는지」의 말 설명만 보여 준다. v0.1은 서버가 없어 숨은 시험도 페이지 안에 들어 있다. 진짜로 숨기는 것은 v0.2 서버에서 한다.
- 「실행」은 공개 시험 없이 그냥 돌려 출력만 본다. 「제출」은 모든 시험으로 채점한다.

### 4-4. 힌트와 정답

1. 문제 다시 읽기
2. 앞에서 배운 개념 떠올리기 (개념 카드로 이동하는 단추)
3. 접근 방향
4. 뼈대 코드

정답과 해설은 **세 번 제출한 뒤**, 또는 「정답 보기」를 누를 때 보여 준다. 힌트나 정답을 봐도 벌점은 없다. 다만 「힌트 없이」 보너스를 받지 못하고, 그 개념이 복습 목록에 올라간다.

### 4-5. 오류 설명

영어 원문 오류를 그대로 보여 주고, 아래에 리아 교수가 한국어로 「무슨 오류인지 → 몇 번째 줄인지 → 왜 생겼는지 → 고치는 방향」 순서로 설명한다. 줄 번호는 Traceback에서 읽어 입력창의 그 줄을 강조한다.

| 오류 | 설명 틀 |
|---|---|
| SyntaxError | 문장 규칙 위반: 따옴표·괄호·콜론 확인 |
| IndentationError | if 아래 줄 들여쓰기 |
| NameError | 없는 이름: 오타 또는 정의 전 사용 |
| TypeError | 글자와 숫자 섞기: `str()`·`int()` |
| ValueError | 숫자로 바꿀 수 없는 값 |
| 그 밖 | 오류 이름과 원문만 보여 주고 「처음 보는 오류예요. 줄 번호부터 볼까요?」 |

설명 틀에 없는 오류라도 앱이 멈추면 안 된다.

## 5. 게임 장치

### 5-1. XP

| 행동 | XP |
|---|---|
| 레슨 완료 | 10 |
| 틀린 문제 없이 완료 | +5 |
| 힌트 없이 직접 작성 통과 | +5 |
| 장 평가 통과 | 30 (레슨 완료 10 대신) |
| 복습 한 판 (취약 개념 문제 5개) | 10 |

이미 끝낸 레슨을 다시 하면 XP 10(장 평가 15)이고 보너스·바이트는 없다(실행 기록 C24: 15개 레슨을 다 끝낸 뒤에도 하루 목표를 채울 수 있게).

### 5-2. 하루 목표와 연속 기록

- 하루 목표: 10·20·30 XP, 기본 20.
- 휴대폰 현지 날짜 기준으로 목표를 채운 날마다 연속 기록이 +1이 된다.
- 기록 보호권: 200바이트, 최대 2개. 목표를 못 채운 날이 하루면 다음 접속 때 자동으로 1개를 쓴다. 이틀 이상 빠지면 빠진 날 수만큼 쓰고, 모자라면 보호권은 쓰지 않고 남겨 둔 채 기록만 0이 된다(실행 기록 C13).
- 7·30·100일에 축하 화면과 보상(7일 50바이트, 30일 우주인 의상, 100일 배지)을 준다.
- 기록이 끊길 때 죄책감을 주는 문구는 쓰지 않는다.
- 휴대폰 시계를 앞으로 돌리는 경우는 막지 않는다(혼자 쓰는 판이라서).

## 6. 리아 교수

### 6-1. 설정

- 이름: 문리아. 「리아 교수님」으로 부른다.
- 컴퓨터공학 박사, 현업 소프트웨어 엔지니어 출신. 가상의 인물이며 실존 인물의 경력을 따오지 않는다.
- 외모: 2.5등신 치비. 짙은 남색 올림머리에 청록 브릿지 한 줄, 갈색 눈, 기본 의상은 밝은 터틀넥 + 짙은 회색 재킷 + 청록·노랑 뱀 브로치.

### 6-2. 말투

- 존댓말 「~해요」체. 차분하고 여유 있으며 가볍게 장난을 친다.
- 칭찬은 구체적으로 한다. 「좋아요!」 대신 「`elif`로 경우를 나눈 게 깔끔해요」.
- 실수를 부끄럽게 만들지 않는다. 오류는 「단서」로 부른다.
- 농담은 Python에 얽힌 가벼운 것으로 한다.
- 첨부 지시서의 「관능적 분위기」 항목은 쓰지 않는다. 다정하고 재치 있는 선배 교수 톤이다.
- 정답을 먼저 알려 주지 않고 생각을 유도한다(힌트 단계 규칙을 따름).

### 6-3. 대사 표

상황(인사, 정답, 연속 정답, 오답, 실행 중, 오류, 힌트, 레슨 완료, 기록 갱신, 기록 끊김, 의상 구매, 오랜만의 접속)마다 3~5줄을 두고, 무작위로 고르되 같은 대사가 연달아 나오지 않게 한다. 대사에 `{name}`(학습자 이름, 선택 입력)·`{streak}` 같은 자리 표시를 쓸 수 있다.

### 6-4. 표정과 효과

- 표정 8가지: 미소(기본), 기쁨(눈 감고 웃음), 반짝, 생각(턱 짚기), 놀람, 걱정(땀방울), 응원(주먹), 장난(윙크).
- 효과음 말풍선: 정답 「딩동!」, 3연속 정답 「척척!」, 실행 중 「타닥타닥」, 오류 「어라?」, 완료 「짠!」.
- 움직임: 평소에는 숨 쉬듯 위아래로 2px, 정답이면 폴짝. 「동작 줄이기」 설정이 켜진 기기에서는 움직이지 않는다.

### 6-5. 그리는 방식

이미지 파일 없이 SVG 코드로 그린다. 부품을 몸·의상 → 목·얼굴 → 표정 → 머리 → 모자·소품 순서로 겹쳐, 의상 9벌 × 표정 8가지를 자유롭게 조합한다. README와 설계 확인용 PNG는 스크립트로 뽑는다.

### 6-6. 소리

Web Audio로 짧은 음을 합성한다(정답, 오답, 완료, 레벨업, 구매). 설정에서 끌 수 있고, 아이폰 무음 모드를 따른다.

## 7. 저장

- `localStorage` 한 칸(`SAVE_KEY = "ria-python.save"`)에 JSON 하나로 저장한다.
- 최상위에 `saveVer`(현재 1)를 두고, `migrate(old)` 함수가 옛 형식을 새 형식으로 옮긴다. 읽기에 실패하거나 깨진 저장이면 새 저장으로 시작하되, 깨진 원본은 `ria-python.save.broken`에 남긴다.
- 학습자 상태의 이름은 첨부 설계서의 진도 항목과 맞춘다: `current_chapter`, `current_lesson`, `completed_lessons`, `submission_logs`(최근 50개), `grading_results`, `weak_concepts`, `review_queue`, `last_active_at`. 여기에 게임 상태 `xp`, `bytes`, `streak`, `freezes`, `quests`, `badges`, `outfits`, `outfit`, `settings`를 더한다.
- 취약 개념 점수: 개념별로 틀리면 +2, 힌트나 정답을 보면 +1, 맞히면 −1(0 미만 없음). 2 이상이면 복습 목록에 올린다.
- 저장은 레슨이 끝날 때와 구매·설정 변경 때 한다. 레슨 중간 상태는 저장하지 않는다(앱을 닫으면 그 레슨은 처음부터).
- **아이폰 대응**: 첫 레슨이 끝나면 「홈 화면에 추가」 안내를 그림으로 보여 준다(사파리 웹사이트 상태로는 7일 동안 방문하지 않으면 저장이 지워질 수 있음). `navigator.storage.persist()`를 요청한다. 설정에 저장 내보내기(파일 받기)·가져오기를 둔다.

## 8. 기기와 성능

- 노치·다이내믹 아일랜드·홈 막대 영역(`env(safe-area-inset-*)`)을 피해 배치한다.
- 화면 키보드가 열리면 `visualViewport`를 따라 입력창과 「실행」 버튼을 키보드 위에 둔다.
- 입력칸 글자는 16px 이상(사파리 자동 확대 방지), 터치 영역은 최소 44pt.
- 정답·오답은 색 + 아이콘 + 글자로 표시하고, 명도 대비는 WCAG AA를 맞춘다.
- 홈 화면 앱: `manifest.webmanifest` + `sw.js`. 게임 파일은 네트워크 먼저·끊기면 저장본을 쓰고, Pyodide 파일은 저장본 먼저(버전 고정 주소)를 쓴다.
- Pyodide는 외부 패키지 없이 기본만 받는다. 버전은 하나로 고정하고 README에 적는다.

| 항목 | 목표 (iPhone 17) |
|---|---|
| 첫 화면 표시 | 2초 이내 |
| Pyodide 준비 (처음) | 와이파이에서 10초 이내, 홈 화면에서 미리 받기 시작 |
| Pyodide 준비 (두 번째부터) | 2초 이내 |
| 일반 문제 실행 결과 | 0.5초 이내 |
| 애니메이션 | 60프레임 이상 |
| 배포 HTML 크기 | 700KB 이하 (Pyodide 제외, 실행 기록 C28) |
