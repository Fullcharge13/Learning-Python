# 화면 출력 점검표 (v0.19.2 작업 2, 2026-11-14)

설계: `docs/specs/2026-11-14-보안-안정성-다듬기-설계.md` §3-2 · 시험: `tests/unit/output_escape.test.js`, `tests/flow.py`의 `test_xss_*`

## 요약

- **범위**: `src/**/*.js`에서 HTML 글자를 화면에 넣는 곳 전부. `innerHTML` 대입 **75곳**(`insertAdjacentHTML`·`outerHTML`·`document.write`·`srcdoc`는 0곳) + `el()`(template.innerHTML) 호출 **6곳** = **직접 넣는 곳 81곳**. 그 밖에 HTML 조각을 넘겨받는 창 `dialog({ body })` **10곳**, 고르기 창 `sheet({ html })` **14곳**, HTML·SVG 글자를 돌려주는 함수 약 40개(아래 표)를 같이 봤다.
- **고친 곳: 3곳(모두 `src/ui/garden.js`)**. 셋 다 실제로 스크립트가 돌았다(Playwright로 `window.__xss`가 1이 되는 것을 확인한 뒤 고침).
  1. `garden.js:459` 노드 「+」 단추의 `data-parent="${parent}"` — **저장 가져오기**의 텃밭 노드 id(빈 글자가 아니면 아무 글자나 저장 정리를 통과)가 escape 없이 속성에 들어감 → 텃밭 화면을 여는 것만으로 속성 탈출(`" onmouseover="…`, `"><svg onload=…>`, `"><img src=x onerror=…>` 실행).
  2. `garden.js:204-210` `stepperHTML`의 `<output>${v}</output>` — **저장 가져오기**의 조건 노드 숫자(`cond.num`, `cond.store.num`)가 글자여도 그대로 들어감 → 조건 고르기 창을 열면 `<img src=x onerror=…>` 실행.
  3. `garden.js:556` 재생 중 「지금 줄」 `<span class="g-ln">${line}</span>` — **작업자 결과**(텃밭 사건의 `line`). 학습자 코드가 `import js; js.eval(…)`로 작업자의 `postMessage`를 감싸 결과를 바꿀 수 있고(아래 「작업자 결과」), 그 값이 escape 없이 들어감 → 코드 모드 텃밭 코드를 「실행」하면 앱 화면(같은 출처)에서 스크립트 실행.
  - 같은 자리 덧붙임(방어): `data-slot`, `stepperHTML`의 `id`·`data-min`·`data-max`도 `esc()`, 「지금 줄」 찾기 선택자는 `CSS.escape`.
- **나머지 78곳은 안전**: 학습자·파이썬·저장 가져오기 값은 이미 `esc()`(또는 `textContent`)를 거치거나, 저장 정리(`migrate`·`cleanGarden`·`cleanGuard`·`cleanDaily`)가 숫자·정해진 id로 바꾼 값만 들어간다.
- **`esc()`**(`src/ui/dom.js:6`, `src/chart.js:21`): `& < > " '` 다섯 글자를 모두 바꾼다 → 큰따옴표·작은따옴표 속성 안에서도 안전.
- **`t```·`tk`·`tp`·`tx`는 escape하지 않는다**(`src/i18n.js`). 넣는 값은 부르는 쪽이 `esc()`해야 한다. 점검한 모든 곳에서 학습자·저장·파이썬 값은 `t``${esc(x)}``` 또는 `esc(t``…${x}…``)` 꼴이었다(번역 문구 자체만 escape 없이 들어감).
- **빌드 신뢰(trusted-by-build)** — 우리 저장소가 만들고 빌드가 묶는 값. 기록만 하고 바꾸지 않았다: 앱 고정 문구, 한국어 번역 열쇠, **영어 묶음**(`lang/en-<지문>.json`), 레슨·개념 카드·문제·힌트·정답(`lessons/ch*.json`), 경비실 사건(`guard/ch*.json`), 텃밭 주문·성장·쪽지(`data/garden.js`), 배지·의상·퀘스트·대사 표(`data/*.js`), 리아·크로우 그림 조각(`data/ria_set2.js`, `data/crow.js`), 오류 안내 묶음(`js/errors-<지문>.js`), 판 번호.
- **영어 묶음 메모**: 실행 중에 받는 JSON이지만 주소는 빌드가 넣은 `window.RIA_LANG_FILES`(같은 출처 `lang/en-<지문>.json`, 개발판은 `i18n/en/*.json`)뿐이고 사용자가 바꿀 길(쿼리·저장·localStorage)이 없다. 영어 문구는 여러 곳에서 escape 없이 속성(`aria-label="${t`…`}"`)이나 본문에 들어가므로 **영어 묶음에 HTML을 넣으면 그대로 해석된다** — 묶음은 코드와 같은 신뢰로 다룬다(검토 없이 밖에서 받은 번역을 넣지 않기). 지금 묶음에서 `<`·`"`가 든 문구 20개(`(?P<name>…)`, `href="..."` 등)는 모두 `esc()`를 거치는 자리에서만 쓰였다.
- **작업자 결과(파이썬 출력)는 학습자가 아무 모양으로나 만들 수 있다**: 실행기는 builtins·sys.modules를 되돌리지만 작업자 JS 전역은 되돌리지 않는다. `import js; js.eval("self.postMessage = …")`로 감싸면 그 뒤 모든 실행 결과(다른 레슨 포함, 작업자를 새로 띄울 때까지)를 바꿀 수 있다. 그래서 `stdout`·`error`·`charts`·`missing`·`farm`·`guard`의 모든 칸을 **믿지 않는 입력**으로 봤다. `cleanResult`(`src/pyrun.js:60`)는 `error.line`을 정수로, `charts`를 `cleanCharts`로 다듬지만 `farm.events`의 칸(`line`·`dir`·`text`…)과 `guard`는 모양만 본다 → 화면 쪽 escape가 마지막 방어선이다.

## 값 출처 표기

고정 = 앱 고정 문구·아이콘 · 번역 = `t``…``·`tx` 등(영어 묶음, 빌드 신뢰) · 데이터 = 레슨·사건·텃밭 표(빌드 신뢰) · 학습자 = 코드·이름·튜토리얼 입력·노드 값 · 파이썬 = 작업자 결과 · 가져오기 = 저장 가져오기·localStorage 저장(다른 탭·만든 저장 포함) · 숫자 = 계산했거나 저장 정리가 숫자로 맞춘 값

## 점검 중 본 것(이번 작업 밖, 기록만)

- 학습자 코드가 작업자를 바꾸면 채점 결과(통과 여부)도 바꿀 수 있다 — 보안(남의 화면)이 아니라 학습 기록의 정직성 문제. 작업자 JS 전역까지 실행마다 되돌리거나 `js` 모듈을 막는 것은 큰 변경이라 따로 판단이 필요하다.
- 바뀐 작업자가 재생 사건의 방향을 `"toString"` 같은 글자로 주면 `facingMark`가 TypeError를 내 재생이 멈춘다(스크립트 실행은 아님).
