# v0.22.0 레벨과 상점 — 설계

작성 2026-11-17 · 브랜치 `feature/levels` (main 6206eb2에서 갈라짐)

## 1. 왜 하나

이 앱에서 바이트를 쓸 곳은 의상실 8벌과 기록 보호권, 두 가지뿐이다. 그래서 공부할수록 보상이 커진다는 느낌, 즉 학습 레벨링 보상이 없다.

- 사용자 말로는 이렇다: 「바이트를 쓸 수 있는 곳이 의상실과 보호권뿐이라 사용자에게 학습 레벨링에 대한 보상이 제대로 구현되지 않음」.
- 레벨 자체가 없다. XP는 쌓이기만 하고, 그 숫자로 열리는 것이 없다.
- 텃밭·경비실·공방은 XP만 주고 바이트를 주지 않아서 바이트 경제와 떨어져 있다.
- 하루 바이트 중앙값은 36.8로, 참고 목표 40~50(v0.1 설계 5-4) 밖이다. 첫 의상은 3.5일째로 목표 3~4일 안이다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

**목표**
- XP로 오르는 레벨을 만든다. 어디서 번 XP든 레벨로 이어진다.
- 레벨이 오르는 순간 바이트를 선물로 준다. 이 선물이 레벨업 보상의 바이트 몫이다.
- 레벨 구간마다 상점 상품이 열리고, 바이트로 산다.
- 오래 공부한 사람이 업데이트 뒤에 손해 보거나 서운하지 않게 한다.
- 시뮬레이션에서 하루 바이트 중앙값 40~50, 첫 의상 3~4일째를 맞춘다.

**하지 않을 것**
- 배움 자체(힌트, 레슨, 심화 열기)를 바이트로 팔지 않는다.
- 공간마다 바이트를 따로 붙이지 않는다(사용자 선택 A).
- 진짜 돈 결제나 랭킹은 없다.

**실패로 보는 것**
- 학습자가 상점을 금방 다 사서 레벨이 올라도 더는 열리는 것이 없다.
- 기존 학습자의 바이트·의상·연속 기록이 줄거나 사라진다.
- 레벨이 오르는데 아무 일도 일어나지 않거나, 반대로 축하 창이 공부를 자꾸 끊는다.
- 바이트가 모자라 공부를 못 하는 상황이 생긴다. 바이트로 막힌 학습 기능은 없어야 한다.

## 3. 사용자가 고른 것

| 물음 | 고른 답 |
|---|---|
| 큰 방향 | **C. 레벨 + 해금 + 바이트**: XP로 레벨이 오르고, 레벨이 오르면 상품을 살 자격이 열리고, 사는 데 바이트를 쓴다 |
| 상품 종류 | **C. 섞기**: 기존 의상 8벌을 레벨에 나눠 걸고, 새 의상 2~3벌, 공간 꾸미기, 편집기 색 테마 |
| 바이트 들어오는 길 | **A. 레벨업 선물**: 각 공간 보상은 XP 그대로 두고, 레벨이 오를 때 바이트를 준다 |
| 기존 학습자 | **A. 레벨은 맞추고 환영 선물 한 번(상한)**: 모은 XP만큼 레벨과 상품 자격을 바로 주고, 지나간 레벨업 선물 대신 환영 선물을 한 번 준다. 이미 산 의상은 그대로 |
| 기존 의상 8벌의 레벨 제한 | **A. 기존 학습자만 예외**: 업데이트 전부터 쓰던 학습자는 원래 8벌을 레벨과 상관없이 지금처럼 살 수 있다. 새 의상·꾸미기·편집기 색은 모두에게 레벨 제한. 새로 시작한 학습자는 8벌에도 레벨 제한 |

## 4. 생각한 방법들

**큰 방향**
- A. 꾸밀 거리만 늘리기: 학습 내용은 건드리지 않지만 실력과 관계없는 「모으면 산다」 구조가 그대로 남는다.
- B. 학습 도구를 바이트로 팔기: 배움에 값을 매기는 셈이라 바이트가 모자란 학습자가 손해를 본다. 버렸다.
- **C. 레벨 + 해금 + 바이트**: 실력이 쌓인 만큼 살 수 있는 것이 늘고, 모든 공간의 XP가 레벨로 모인다. **골랐다.**

**바이트 길**
- **A. 레벨업 선물**: 고칠 곳이 레벨업 한 곳뿐이고, 모든 활동이 같은 길로 보상된다. **골랐다.**
- B. 공간마다 따로: 바로 체감되지만 공간을 하나 늘릴 때마다 균형을 다시 잡아야 한다.
- C. 둘 다: 너무 많이 버는 것을 막기 어렵다.

## 5. 설계

### 5-1. 레벨 곡선 (만드는 사람의 판단, 시뮬레이션으로 확인)

- 레벨은 1부터 30까지다. 레벨 n에서 n+1로 가는 데 필요한 XP는 `30 + 10 × (n − 1)`이다.
  - 1→2는 30 XP, 2→3은 40 XP, 29→30은 310 XP다.
  - 레벨 L에 닿는 누적 XP는 `30 × (L − 1) + 5 × (L − 1) × (L − 2)`이다. 레벨 2는 30, 레벨 10은 630, 레벨 13은 1,020, 레벨 30은 4,930이다.
  - 작업 3 시뮬레이션 판정에서 첫 숫자를 60에서 30으로 낮췄다. 60이면 30일째 레벨 중앙값이 9로 목표(10~14) 밖이었다. 근거: `docs/research/2026-11-17-레벨-경제-판정.md`.
- 근거: 본 과정 85개, 심화 51개, 매일 도전, 경비실·텃밭·공방을 다 하면 대략 4,000~4,500 XP가 나온다. 30레벨은 다시 하기나 복습까지 꾸준히 하는 사람이 닿는 끝이다.
  - 대개 둘째 날, 빠르면 첫날 레벨 2에 닿는다(레슨 하나 10~20 XP, 시뮬레이션 12판 중 5판이 첫날, 12판 모두 둘째 날까지). 「첫 레벨업은 이틀 안」.
  - 30일째 레벨 목표는 10~14다. 기준 시뮬레이션(§5-6)의 중앙값은 12다(12판 중 10판이 12, 2판이 11). 이 범위를 벗어나면 곡선의 두 숫자(30, 10)를 조정한다(만드는 사람의 판단, LOG에 적음).
  - 90일 판(본 과정 + 심화 + 매일 도전 + 텃밭)은 90일째 레벨 25 안팎이다. 레벨 30은 다시 하기나 복습까지 꾸준히 하는 사람이 닿는 끝으로 남는다.
- 레벨은 늘 `save.xp`에서 계산한다(`levelOf(xp)`). 레벨을 따로 저장하지 않으므로 둘이 어긋날 일이 없다.
- 레벨 30을 넘은 XP는 레벨을 더 올리지 않는다. 「최고 레벨」로 표시한다.

### 5-2. 레벨업 선물

- 레벨 L에 오르면 `10 + 2 × L` 바이트를 준다. 레벨 2는 14, 레벨 10은 30, 레벨 30은 70이다.
  - 2~30레벨을 모두 합치면 1,218바이트다.
  - 작업 3 시뮬레이션 판정에서 첫 숫자를 20에서 10으로 낮췄다. 곡선을 낮춰 레벨이 더 자주 오르므로, 20이면 하루 바이트 중앙값이 50.9로 목표(40~50) 밖이었다.
- 한 번에 여러 레벨이 오르면 선물을 모두 더해 한 번에 알린다. 예를 들어 큰 평가 하나로 두 레벨이 오를 수 있다.
- 받은 레벨은 `save.levels.granted`(받은 최고 레벨)에 적는다. 같은 레벨 선물을 두 번 받지 않는다.
- 선물 바이트는 바이트 출처의 하나로 결과 화면에 보인다: 레슨 / 퀘스트 / 연속 / **레벨**.
- 시뮬레이션 결과를 보고 숫자만 조정할 수 있다(목표 §2). 조정한 값은 LOG에 적는다.

### 5-3. 축하

- 레슨 결과 화면, 매일 도전, 텃밭·경비실·공방의 통과 창처럼 XP가 들어오는 자리에서 레벨이 오르면 축하를 한 줄 덧붙인다.
  - 예: 「레벨 7! 떡잎이 됐어요 · +24바이트 · 새 상품 2개」.
  - 따로 창을 띄워 공부를 끊지 않는다.
- 홈 상태 줄의 XP 옆에 레벨 표시(`Lv 7`)와 다음 레벨까지의 막대를 둔다.
- 레벨 이름은 5레벨마다 바뀐다. 6단계: 새싹(1~5) → 떡잎(6~10) → 정원사(11~15) → 탐험가(16~20) → 연구원(21~25) → 마스터 파이썬(26~30). 영어는 Sprout, Seedling, Gardener, Explorer, Researcher, Python Master이다. 만드는 사람의 판단이며, 이름은 바꿀 수 있다.

### 5-4. 상점

- 의상실을 「상점」으로 넓힌다. 탭은 의상, 꾸미기, 편집기 색이다. 바닥 메뉴의 이름과 그림은 그대로 둔다.
- 상품마다 `level`(열리는 레벨)과 `price`가 있다. 레벨이 모자라면 「Lv 12에 열려요」라고 보여 주고 살 수 없다. 레벨이 되면 바이트로 산다.
- 구간 배치(초안, 만드는 사람의 판단): 5레벨마다 의상 1~2개와 꾸미기·색 1~2개.

| 레벨 | 의상 | 꾸미기·편집기 색 |
|---|---|---|
| 1 | 캐주얼룩 100 | 편집기 색 「종이」 100 |
| 3 | 후드티 180 | 텃밭 울타리 장식 100 |
| 5 | 체육복 180 | 편집기 색 「숲」 100 |
| 8 | 요리사 180 | 경비실 화면 테마 「야간 근무」 120 |
| 10 | 화이트 코트 180 | 공방 진열장 받침 「나무」 120 |
| 13 | 탐험가 240 | 텃밭 꽃길 140 |
| 15 | 교복 240 | 편집기 색 「바다」 150 |
| 18 | **새 의상 ①** 300 | 경비실 테마 「관제실」 180 |
| 20 | 마법사 망토 300 | 공방 받침 「금속」 180 |
| 23 | **새 의상 ②** 360 | 편집기 색 「밤하늘」 200 |
| 26 | — | 텃밭 온실 장식 240 |
| 28 | **새 의상 ③** 400 | — |

  - 합계는 의상 2,660, 꾸미기·색 1,630, 모두 4,290바이트다.
  - 작업 3 시뮬레이션 판정에서 「종이」를 60에서 100으로, 울타리를 80에서 100으로 올렸다. 시뮬레이션 학습자는 열린 상품 중 가장 싼 것부터 사므로, 두 꾸미기가 캐주얼룩(100)보다 싸면 첫 의상이 7일째로 밀렸다. 100으로 맞추면 값이 같을 때 의상 먼저(§5-6 사는 규칙)라 캐주얼룩을 먼저 사서 첫 의상이 3일째가 된다.
  - 버는 쪽은 90일 판(본 과정 + 심화 + 매일 도전 + 텃밭) 중앙값으로 레슨·퀘스트·연속 기록·매일 도전·텃밭 약 3,400과 레벨 선물 약 900(90일째 레벨 25 안팎)을 더해 약 4,300이다. 보호권(90일에 5~6개, 약 1,100)까지 쓰면 90일째에 상품이 3~4개 남는다(중앙값 3.5). 꾸준히 하는 사람이 마지막 구간에서 「살 것이 아직 하나쯤 남아 있는」 정도가 맞다.
- 기존 의상 값(100~300)은 그대로 둔다. 기존 학습자가 이미 낸 값과 어긋나지 않게 하기 위해서다.
- 졸업 가운은 지금처럼 30일 연속 기록으로 얻는다. 기본복장은 처음부터 있다.
- 새 의상 3벌은 기존 리아 SVG 방식(`src/ria.js`)으로 그린다. 모습은 따로 정하지 않았다. 아래 「만드는 사람에게 맡기는 것」을 본다.
- **꾸미기는 산 뒤에 켜고 끌 수 있다.** 공간마다 한 번에 하나를 쓰고, 기본값은 「없음」이다.
  - 텃밭 장식: 텃밭 화면 테두리와 배경의 작은 그림.
  - 경비실 테마: 경비실 화면의 색 묶음. 대비 기준 4.5:1을 밝은 화면과 어두운 화면 모두에서 지킨다.
  - 공방 진열장 받침: 진열장 칸 아래의 받침 그림.
- **편집기 색**은 코드 편집기의 글자 색 묶음이다. 밝은 화면과 어두운 화면에서 각각 대비 기준을 지킨다. 기본값은 지금 색이다.
- 기록 보호권은 상점 안에 그대로 있다. 값 200, 레벨 제한 없음.

### 5-5. 기존 학습자 옮기기 (사용자 선택 A)

- 업데이트 뒤 처음 열 때 `save.levels`가 없으면 이렇게 한다.
  - `levelOf(xp)`로 지금 레벨을 정하고 `granted`를 그 레벨로 적는다. 지나간 레벨 선물은 주지 않는다.
  - 환영 선물로 `min(10 × (레벨 − 1), 200)` 바이트를 한 번 준다. 레벨 1이면 0, 레벨 21 이상이면 200(상한)이다.
  - 작업 3에서 곡선을 낮춰 같은 XP가 2레벨쯤 높게 나오므로 환영 선물도 약 20바이트 커졌고, 상한 200은 2,500 XP(전에는 3,100)에서 닿는다. 지나간 선물에 견주면 여전히 3분의 1 정도라 그대로 둔다.
  - 홈에서 한 번 알린다. 예: 「레벨이 생겼어요! 지금 Lv 14 · 환영 선물 +130바이트」. `pending_refund`와 같은 방식으로 한 번 알리고 지운다.
- 이미 산 의상과 꾸미기는 레벨과 상관없이 그대로 가진다. 레벨이 모자라도 「가지고 있음」이다.
- **기존 학습자 예외(사용자 선택 A)**: 옮기기를 거친 저장에는 `levels.legacy = true`를 적는다. 이 표시가 있으면 원래 의상 8벌(캐주얼룩, 화이트 코트, 후드티, 체육복, 요리사, 탐험가, 교복, 마법사 망토)은 레벨과 상관없이 바이트만 있으면 살 수 있다. 상점에서는 레벨 표시 대신 「예전부터 함께한 학습자」 표시를 둔다. 새 의상 3벌, 꾸미기, 편집기 색은 `legacy`여도 레벨 제한을 따른다.
- 「기존 학습자」는 업데이트 뒤 처음 열 때 `levels`가 없고 **XP가 0보다 큰** 저장이다. XP 0인 저장(새로 시작했거나 아무것도 안 한 저장)은 새 학습자로 본다.
- 바이트, 연속 기록, 보호권은 바뀌지 않는다. 환영 선물만 더한다.
- 새로 시작한 학습자는 레벨 1, `granted` 1, 환영 선물 0이다.
- 저장 형식: `saveVer`를 올리지 않고 clean-or-default 하위 묶음 `levels: { granted, pending_welcome, legacy }`와 `deco: { owned: [], on: { garden, guard, workshop, editor } }`를 더한다. 경비실·텃밭·공방을 더할 때와 같은 방식이다. 깨진 값은 기본값이 된다. 단, 깨진 `levels`라도 지나간 선물을 다시 주지 않도록 `granted`의 기본값은 `levelOf(xp)`이다.
- 개발자 모드 저장 칸은 지금처럼 따로 쓴다.

### 5-6. 확인할 것 (성공의 증거)

- 단위 시험:
  - `levelOf`의 경계값(29, 30, 69, 70, 4929, 4930, 그 이상). 곡선을 조정하면 경계값도 같은 식에서 다시 계산한다.
  - 선물 합산(한 번에 여러 레벨), 같은 선물을 두 번 주지 않음.
  - 옮기기 환영 선물의 상한, 깨진 저장, 레벨이 모자란 상품 사기 거절.
  - `legacy` 저장은 원래 8벌을 레벨 없이 살 수 있고 새 상품은 거절, 새 저장은 8벌도 거절. XP 0 저장은 `legacy`가 아님.
- 시뮬레이션 `tests/sim/economy.js`:
  - **기준 판**은 지금 기본 실행(`runSim(seed)`, 심화·매일 도전·텃밭 없음)이고, **기준 수치**는 `bytesPerActiveDay`다(오늘 36.8). 여기에 레벨 선물을 넣고 30일 × 12판에서 하루 바이트 중앙값 40~50, 첫 의상 3~4일째인지 본다. 「매일 도전 + 텃밭」 판의 같은 수치도 함께 적되, 판정은 기준 판으로 한다.
  - 30일째 레벨 중앙값을 적는다(목표 10~14).
  - **사는 규칙**(시뮬레이션 학습자): 학습한 날 끝에 보호권이 0개이고 200바이트 이상이면 보호권을 먼저 산다. 그다음 레벨이 열린 상품 중 가장 싼 것을 종류와 상관없이 하나씩 산다. **값이 같으면 의상을 먼저 사고**, 그다음 상품 표 순서를 따른다. 첫 의상 판정이 이 순서에 달려 있다(「종이」·울타리·캐주얼룩이 모두 100). `tests/unit/economy_sim.test.js`가 지킨다. 「첫 의상」은 첫 의상을 산 날로 따로 잰다.
  - **90일 판**: 「본 과정 + 심화 + 매일 도전 + 텃밭」 학습자를 90일까지 돌린다. 90일째에도 아직 사지 않은 상품(열렸든 안 열렸든)이 적어도 1개 남아 있어야 통과다. 12판 중앙값으로 본다.
- 흐름 시험:
  - 레슨으로 레벨업 → 결과 화면에 축하 줄과 선물 → 상태 줄의 레벨.
  - 상점에서 잠긴 상품, 산 상품 켜고 끄기.
  - 기존 저장을 불러온 뒤 환영 알림이 한 번만 나오는지.
  - 다시 들어오기, 영어, 개발자 모드.
- 대비: 새 꾸미기와 편집기 색 각각을 밝은 화면과 어두운 화면에서 검사한다(밝게 `--compare`, 어둡게 strict 0).

## 6. 만드는 사람에게 맡기는 것

- 새 의상 3벌의 모습과 이름. 기존 그림 방식과 팔레트 안에서, 실존 캐릭터나 브랜드를 따라 하지 않는다.
- 꾸미기와 편집기 색의 정확한 색 값과 그림. 대비 기준은 지킨다.
- 상점 화면 배치(탭 모양, 잠긴 상품 표시). 375px 휴대폰과 어두운 화면에서 동작해야 한다.
- 레벨 곡선과 선물 숫자의 미세 조정. §2의 시뮬레이션 목표 안에서 하고, LOG에 적는다.
- 공방 진열장 받침을 넣는 정확한 위치처럼, 기존 화면에 꾸미기를 끼워 넣는 자리.
