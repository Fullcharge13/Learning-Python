# 프로젝트 공방 (v0.21.0) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 장을 끝내면 열리는 단계별 미니 프로젝트 5개와, 완성작을 묻고 답하며 실행하는 공방을 만든다.

**Architecture:** 실행기(`runner.py`)에 「주고받기」(입력이 모자라면 오류 대신 입력 필요 결과)와 「정해 둔 무작위」(채점용)를 더하고, JS 쪽 `src/projects/console.js`가 「멈췄다 다시 돌리기」로 한 판을 이어 간다. 프로젝트는 레슨처럼 언어별 데이터(`data/projects.js`, `data/projects.en.js`)를 빌드가 색인 + 따로 받는 파일로 나누고, 단계는 레슨 `mountWrite`를 그대로 재사용한다. 진행은 새 저장 칸 `save.projects`(`src/projects/state.js`).

**Tech Stack:** 바닐라 JS(ES 모듈, esbuild), Pyodide 314.0.7 작업자, node:test, pytest, Playwright(`tests/flow.py`).

**Spec:** `docs/specs/2026-11-15-프로젝트-공방-설계.md`

## Global Constraints

- 프로젝트 5개: P1 3장 가위바위보, P2 5장 숫자 맞히기, P3 8장 단어장 퀴즈, P4 11장 할 일 목록, P5 14장 날씨 카드. 한 프로젝트 3~5단계.
- 문법은 그 장까지 배운 것만(경비실 `tests/guard_incidents.py`의 표와 같은 기준). 예외는 「새 도구 카드」로 소개한 `import random`, `random.randint`, `random.choice`뿐(프로젝트 검사에서만).
- 채점은 레슨 「직접 쓰기」와 같은 `tests`(`stdin`, `expect`, `public`)·`require`. 무작위가 있는 시험은 `rand: [..]`로 값을 정해 준다(실제 무작위 안 씀).
- 완성작 실행: 멈췄다 다시 돌리기, 한 판 씨앗 고정, 한 판 입력 상한 50번, 실행 시간 제한은 기존 그대로.
- 진행은 시작한 언어에 묶임(`open.<id>.lang`).
- 보상: 단계 첫 통과 XP 5, 완성 XP 20, 바이트 없음. 배지 `project_first` 「첫 작품」, `project_all` 「공방 장인」. XP는 `earnXp` → 퀘스트 `"xp"` 길(경비실 `src/guard/state.js:210` 방식).
- 「모범 코드에서 이어 하기」를 고르면 그 단계 XP 없음.
- 저장 `saveVer` 2 그대로, `save.projects`는 없거나 망가지면 기본값. 개발자 모드는 다른 칸(기존 규칙).
- 단계 `solution`은 빌드에 **남긴다**(레슨처럼 「정답 보기」·「모범 코드에서 이어 하기」에 필요 — 설계서 §4-1 「빠진다」를 이 이유로 바꿈, 판정 W-P1).
- 화면 글은 모두 `esc`. 화면은 `#app`에 묶음을 달면 cleanup에서 반드시 뗀다(v0.20.1).
- 첫 파일 상한(`build.py`) 안. 대비 밝게·어둡게 4.5:1.
- 공격·실존 서비스 이름 없음, 날씨 자료·도시는 가상이어도 되고 실제 도시 이름은 괜찮음(공격 대상 아님).

## Review Focus

1. **한 판의 출력 이어 붙이기:** 다시 돌린 실행의 출력이 앞 실행 출력으로 시작하지 않으면(예: 출력에 시각·무작위가 섞여 매번 달라짐) 화면이 엉킴 → 새 출력 전체로 바꾸고 「처음부터 다시 보여 줘요」 없이 조용히 맞춤. 작업 2 시험 `console: 앞부분이 다르면 전체를 바꿈`.
2. **끝나지 않는 프로그램:** `while True:`에 끝이 없는 완성작이 입력을 계속 요구 → 입력 상한 50에서 멈추고 안내. 작업 2 시험 `console: 입력 상한`.
3. **언어를 바꾼 학습자:** 한국어로 2단계까지 한 P1을 영어로 열면 이어 하기/처음부터 고르기가 나오고, 고른 대로 진행. 작업 6 흐름 `test_workshop_language_switch`.
4. **화면을 나갔다 들어오기:** 공방·프로젝트·주고받기 화면을 드나든 뒤에도 입력·실행이 지금 화면에서 한 번만. 작업 6 흐름 `test_workshop_reenter`.
5. **입력창에 빈 답·아주 긴 답:** 빈 답은 `""`로 넘기고(파이썬 `input()`과 같음), 500자 넘는 답은 잘라 넣음. 작업 2 시험 `console: 빈 답과 긴 답`.

- Test: `tests/py/test_runner_interactive.py`(새), `tests/unit/pyrun*.test.js`(있는 파일에 더함)

**Interfaces:**
- Produces (`runner.py`): `run(code, stdin=None, require=None, files=None, server=None, farm=None, lang=None, guard=None, interactive=False, rand=None, seed=None)`.
  - `interactive=True`이고 입력이 모자라면 오류 대신 결과에 `"need_input": {"prompt": str}`(그 `input()`의 안내 글), `"error": None`. 그 전까지의 출력은 `stdout`에.
  - `rand=[int|str, ...]`: 실행 동안 `random.randint(a, b)`·`random.choice(seq)`가 이 값을 차례로 돌려줌(`choice`는 값이 seq 안에 있으면 그 값, 없으면 오류 `RandMismatch`). 값이 모자라면 오류 `RandMissing`. `rand`가 없으면 진짜 `random`.
  - `seed=int`: 실행 전에 `random.seed(seed)`.
- Produces (`pyrun.js`): `py.run(code, stdin, require, { ...기존, interactive, rand, seed })` → 결과에 `need_input`이 그대로 실림.

- [ ] **Step 1:** 실패하는 pytest — `interactive_needs_input`(입력 2번 필요 코드에 1개만 → `need_input.prompt == "두 번째: "`, stdout에 앞 출력), `interactive_false_keeps_error`(기존처럼 InputMissing 오류), `rand_sequence`(`randint` 두 번 → `[3, 1]` 순서), `rand_choice_in_seq`/`rand_choice_not_in_seq`(오류 종류 `RandMismatch`), `rand_missing`(`RandMissing`), `seed_repeatable`(같은 seed 두 실행 같은 출력).
