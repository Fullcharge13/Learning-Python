# 첫 화면 가볍게 — 설계서 (v0.17.0 후보)

날짜: 2026-11-13 · 브랜치: `feature/first-screen-light` (`feature/guard-room` 0102f25에서)

## 1. 왜 하나

- 사용자 확인: 아이폰 17에서 학습·텃밭이 느리다고 느낀 적은 없다. 문제는 **첫 파일(`dist/index.html`) 자리**다. 한도 850KB(870,400B)에 지금 859,977B, 남은 여유 약 10KB. 다음 콘텐츠(기본·심화 문제, 경비실 사건)를 넣을 자리가 없다.
- 사용자 선택(A): 배우는 사람의 가장 낮은 기기는 **몇 년 된 아이폰·중저가 안드로이드**까지. 그 기기에서 첫 화면이 지금보다 느려지면 안 된다.
- 사용자 선택(방법 1): **큰 덩어리만 따로 떼기**.

## 2. 목표 / 하지 않을 것 / 실패로 볼 것

**목표**
1. 첫 파일 **≤ 520KB**(지금보다 약 340KB 작게). 새 첫 파일 한도 **600KB**(614,400B)로 낮춰 다시 불어나지 않게.
2. 따로 뗀 파일마다 한도: 편집기 묶음 **≤ 420KB**, 오류 안내 묶음 **≤ 40KB**.
3. CPU 4배·6배 + 느린 3G(gzip 켠 로컬 서버)에서 첫 화면까지 걸리는 시간이 **지금보다 짧다**(같은 측정 도구로 전후 비교, 각 3회 중앙값).
4. **오프라인**(서비스 작업자 설치 뒤)에서 레슨 코드 쓰기·경비실 직접 쓰기·텃밭 프로그램이 지금처럼 열린다.
5. 판이 바뀐 직후(새 첫 파일, 옛 편집기 파일)에도 편집기가 열린다.

**하지 않을 것**
- 화면별로 앱을 여러 파일로 다시 짜기(방법 3). 텃밭·레슨 화면 코드는 그대로 첫 파일에.
- Pyodide(파이썬 엔진 약 12MB) 받는 방식 바꾸기. 처음 「실행」 대기는 이번 범위 밖.
- 기능·문구·저장 형식 변경. `saveVer` 2 그대로.

**실패로 볼 것**
- 첫 화면이 지금보다 느려진다(위 측정에서).
- 오프라인·업데이트 직후 편집기나 오류 안내가 안 열린다.
- 편집기를 기다리는 동안 학습자가 입력한 글이 사라진다.
- 영어판에서 한글이 보이거나 i18n 언어가 편집기 쪽과 앱 쪽에서 어긋난다.

## 3. 방식 (사용자가 고른 방법 1)

검토한 방법: ① 큰 덩어리 떼기(고름), ② 그 자리에서 줄이기(20~40KB, 곧 다시 참), ③ 화면별 여러 파일로 다시 짜기(가장 크지만 빌드·서비스 작업자·체험판을 다 손봐야 함). ②의 손쉬운 다이어트는 이번 범위에서 빼고, 필요하면 나중에.

### 3-1. 묶음 두 개를 따로

| 묶음 | 내용 | 파일 이름 |
|---|---|---|
| 편집기 | `src/ui/editor.js`와 CodeMirror·Lezer 전부 | `js/editor-<지문8>.js` |
| 오류 안내 | `data/errors.js`(`ERRORS`, `ERROR_ALIASES`, `ERROR_VARIANTS`) | `js/errors-<지문8>.js` |

- 지문 = 파일 내용 sha256 앞 8자(장 파일과 같은 규칙).
- 빌드는 첫 파일에 `window.RIA_CHUNKS = { editor: "js/editor-….js", errors: "js/errors-….js" }`를 넣는다(장 파일 이름표 `RIA_CHAPTER_FILES`와 같은 방식).
- 개발판(빌드 안 한 `src/index.html`)은 지금처럼 바로 import해도 된다 — 지연 받기는 배포판에서만 꼭 필요.

### 3-2. 받는 때

1. **첫 화면을 그린 뒤 쉬는 틈**(`requestIdleCallback`, 없으면 짧은 `setTimeout`)에 두 묶음을 미리 받기 시작.
2. 편집기가 필요한 화면(레슨 코드 쓰기 문제, 경비실 직접 쓰기, 텃밭 프로그램)을 열 때 아직 안 왔으면 **그 자리에서 기다림**: 편집기 자리에 「코드 입력창 준비 중…」을 보이고, 오면 그 자리에 편집기를 끼운다. 시작 코드(`doc`)는 그대로 넘긴다.
3. 오류 안내는 오류 카드를 그릴 때 필요. 코드 실행에는 Pyodide 준비가 먼저 필요하므로 보통 이미 와 있다. 아직 없으면 오류 카드는 **기다렸다가** 그린다(짧은 「단서 찾는 중…」). 받기가 실패하면 오류 종류·줄 번호만 있는 간단한 카드(한·영 문구 새로 2개)로.
4. 받기 실패(오프라인인데 저장본도 없음 등)면 편집기 자리에 「코드 입력창을 불러오지 못했어요. 인터넷에 연결한 뒤 다시 열어 주세요」(한·영)와 「다시 시도」 단추.

### 3-3. 서비스 작업자

- 설치 때 미리 받는 목록(`GAME_FILES`)에 두 묶음을 넣는다. 판이 바뀌면 새 지문 파일을 받고, 옛 캐시는 지금 규칙대로 정리.
- **업데이트 직후 안전**: 새 첫 파일이 가리키는 새 지문 파일은 새 캐시에 있다. 옛 첫 파일(새 작업자가 활성되기 전 열린 탭)이 옛 지문 파일을 찾을 때도 옛 캐시가 지워지기 전이면 받아지고, 지워졌으면 네트워크로. 오프라인 + 옛 탭 + 옛 캐시 삭제가 겹치면 3-2의 4번 실패 화면.

### 3-4. i18n과 상태 공유

- 편집기 묶음은 앱의 `i18n.js`를 **다시 묶지 않는다**(두 벌이면 언어 상태가 어긋남). `createEditor`는 화면 글(예: 「코드 입력창」 라벨)을 **인자로** 받거나, 앱이 넘긴 `t`를 쓴다.
- 오류 안내 묶음은 데이터만. 영어 문구는 지금처럼 영어 언어 파일(`lang/en-*.json`, 이미 지연)에.

### 3-5. 한도와 시험

- `build.py`: 첫 파일 `MAX_RAW` 850KB → **600KB**. 묶음별 한도(편집기 420KB, 오류 40KB)를 넘으면 빌드를 멈춤.
- `tests/build_test.py`: 첫 파일에 CodeMirror 흔적(`@codemirror`의 고유 글자, 예: `cm-editor`)이 **없음**, `ERRORS` 본문 글(예: `TypeError_concat` 제목)이 **없음**, `RIA_CHUNKS` 두 파일이 있고 지문이 내용과 맞음, `sw.js` `GAME_FILES`에 두 파일, 크기 한도.
- 측정 도구 `tools/perf_first_screen.py`(새로): 빌드 결과를 **gzip 켠** 로컬 서버로 띄우고 아이폰 13 흉내, CPU 4배·6배 × (로컬, 느린 3G)에서 첫 화면 시간 3회 중앙값을 낸다. Pyodide는 `--dev-pyodide` 경로로. 결과를 `LOG.md`에 전후 비교 표로.
- 흐름 시험(`tests/flow.py`)에 추가:
  - 편집기 묶음 받기를 일부러 늦춘 상태에서 레슨 코드 쓰기를 열면 「준비 중」 → 편집기, 시작 코드 그대로.
  - 오프라인(서비스 작업자 설치 뒤 네트워크 끊음)에서 레슨 코드 쓰기·경비실 직접 쓰기·텃밭 프로그램 열기와 오류 카드.
  - 편집기 묶음 받기 실패 → 실패 문구와 「다시 시도」, 다시 시도로 열림.
  - 영어판에서 위 문구에 한글 없음.
- 기존 전체 묶음(npm, pytest, content ko·en, parity, i18n, garden_orders, guard_incidents, grader_browser, build_test, flow, economy, readme) 모두 통과.

### 3-6. 체험판 아티팩트

- `artifact-build/tools/make.py`가 `js/` 폴더를 그대로 복사하는지 확인(지금은 `dist`를 통째로 복사하므로 됨). `.js`가 아티팩트에서 내주어지는지 한 번 확인.

### 3-7. 정해 둔 것 (설계자 판단 — 사용자 검토용)

- **편집기를 기다리는 동안의 화면**: 화면 전체(문제, 힌트, 기호 줄, 단추)는 바로 그린다. 편집기 자리에는 시작 코드를 **읽기 전용 글**로 보이고 그 위에 「코드 입력창 준비 중…」을 겹친다. 그동안 「실행」「제출」과 기호 줄은 꺼 둔다(파이썬 엔진 준비 중일 때와 같은 방식). 입력할 곳이 없으므로 입력한 글이 사라질 일도 없다. 편집기가 오면 자리를 바꿔 끼우고 단추를 켠다. 세 화면(레슨 코드 쓰기, 경비실 직접 쓰기, 텃밭 프로그램)에 같은 도우미를 쓴다.
- **판이 바뀐 뒤 옛 탭**: 배포(gh-pages)는 옛 지문 파일을 남기지 않으므로, 쉬는 틈에 미리 받지 못한 옛 탭은 옛 묶음을 못 찾을 수 있다. 이때 실패 화면은 「새 판이 나왔어요. 새로 고침하면 열려요」와 「새로 고침」 단추(한·영)를 보인다. 첫 화면 직후 미리 받기를 하므로 드물다. 옛 파일을 배포에 남기거나 판을 넘나드는 캐시 찾기는 하지 않는다.
- **체험판 아티팩트**: 아티팩트는 이미 `pyodide/pyodide.mjs`를 같은 곳에서 `import()`로 받아 쓰고 있으므로 `js/*.js`도 같은 방식으로 받을 수 있다. 별도의 「묶음 다시 넣기」 빌드는 만들지 않는다. 확인은 갱신한 체험판에서 레슨 코드 쓰기를 한 번 열어 보는 것으로.

## 4. 판 번호와 기록

- `VERSION = "v0.17.0"`(첫 파일 구조가 바뀌므로). `LOG.md`에 전후 크기·속도 표, `docs/plans/ledger.md`에 「v0.17.0」 판정 표(번호 F-C1…). G3-C12(첫 파일 상한 850KB)는 **F-C1로 바뀜(600KB)** 표시.
- `README.md`는 `tools/readme_gen.py`로만.

## 5. 만드는 사람에게 맡기는 것

- esbuild로 묶음을 나누는 구체 방법(별도 ESM 묶음 + `import()` 주소, 또는 전역에 붙이는 IIFE 묶음). 단, 단일 HTML·Blob 작업자 구조와 iOS Safari 16 이상에서 동작해야 함.
- 「준비 중」 자리표시의 모양(기존 카드·글꼴을 따름).
- `grade.js`가 `ERRORS`를 받는 방법(주입, 비동기 불러오기 등). `normalize`·`judge`는 첫 파일에 남아야 함(빈칸·레슨 채점에 씀).
