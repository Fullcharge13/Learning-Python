# 보안·안정성 다듬기 — 설계서 (v0.19.2 후보)

날짜: 2026-11-14 · 브랜치: `feature/hardening-2` (`main` 93616a0에서)

## 1. 왜 하나

- 미뤄 둔 일 정리에서 사용자가 「추천 순서대로」를 고름 → 첫 묶음이 보안·안정성.
- 보안을 가르치는 앱이 (1) 파이썬 엔진을 외부 CDN에서 받아 원본 확인 없이 실행하고, (2) 화면에 HTML을 넣는 곳(`innerHTML`)을 한꺼번에 점검한 적이 없고, (3) 오프라인 시험 하나가 고정 0.5초 기다림 때문에 가끔 흔들린다.
- 사용자 선택: 엔진은 **A. 우리 사이트에서 직접 내주기**.

## 2. 목표 / 하지 않을 것 / 실패로 볼 것

**목표**
1. 배포판은 파이썬 엔진(Pyodide 314.0.7 핵심 5개: `pyodide.mjs`, `pyodide.asm.mjs`, `pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json`)을 **같은 출처의 `pyodide/`**에서 받는다. 앱은 실행 중 외부 출처에 아무 요청도 하지 않는다.
2. 화면에 HTML을 넣는 모든 곳을 점검해, 학습자 입력·파이썬 출력·오류 메시지·저장 가져오기 값·언어 묶음 문구가 escape 없이 HTML로 해석되는 곳을 없앤다. 점검표를 문서로 남긴다.
3. `tests/build_test.py`의 「업데이트 실패 뒤 오프라인 열기」가 조건을 보고 기다리게 해 20번 연속 통과.

**하지 않을 것**
- Pyodide 판 올리기. 엔진에 지문 확인(B안) 덧붙이기. 기능·문구·저장 형식 변경(`saveVer` 그대로).

**실패로 볼 것**
- 배포판이 jsDelivr 등 외부 주소를 하나라도 부름(시험으로 확인).
- 첫 방문·오프라인·업데이트 뒤에 파이썬이 준비되지 않음.
- 점검에서 「안전하다」고 한 곳이 실제로 HTML을 해석함.

## 3. 설계

### 3-1. 엔진 직접 내주기

- `build.py`: 배포판(`--dev-pyodide` 아닐 때) `RIA_PYODIDE_URL = "./pyodide/"`, 위 5개 파일을 `node_modules/pyodide/`에서 `dist/pyodide/`로 복사. 개발·시험판은 지금처럼 `/node_modules/pyodide/`. 앱은 이미 상대 주소를 절대 주소로 바꿔 작업자에 넘김(`src/pyrun.js`).
- 5개 파일의 sha256이 `node_modules/pyodide`의 원본과 같은지 빌드가 확인(복사 실수 방지).
- `sw.js`: 엔진 저장(`PY_CACHE`)이 같은 출처 `pyodide/` 주소를 대상으로. 설치 때 미리 받기 목록도 같은 주소. 판이 바뀌어도 엔진 캐시 이름은 Pyodide 판 기준이라 다시 받지 않음(지금 규칙 유지).
- `third_party_notices`: 배포 주소를 「같은 사이트의 pyodide/ (원본: npm pyodide 314.0.7)」로, MPL-2.0 고지 유지.
- 체험판 `tools/make.py`(저장소 밖)는 이미 `pyodide/`를 따로 넣음 — `dist/pyodide/`가 생기면 그것을 쓰고 `.zip` 이름 바꾸기만 유지. 체험판 시험(`smoke.py`) 통과.
- README·LOG의 「jsDelivr」 설명 바꿈(판정 C19 → 이번 판정으로 바뀜 표시).

### 3-2. 출력 보안 점검

- 범위: `src/**/*.js`의 `innerHTML`, `insertAdjacentHTML`, `outerHTML`, 템플릿 문자열로 HTML을 만들어 넣는 함수 전부.
- 각 넣는 곳마다 들어가는 값의 출처를 분류: 앱 고정 문구 / 번역 문구(`t```, `tx`) / 레슨·사건 데이터 / 학습자 입력(코드, 이름, 튜토리얼 입력) / 파이썬 출력·오류 / 저장 가져오기 값 / 숫자. 학습자·파이썬·저장 가져오기 값은 반드시 `esc()` 또는 `textContent`.
- 번역 문구와 데이터는 저장소 안에서 우리가 쓰지만, 영어 묶음과 저장 가져오기처럼 밖에서 들어올 수 있는 값은 escape하는지 따로 표시.
- 찾은 문제마다 먼저 실패하는 시험(입력에 `<img src=x onerror=…>`·`"><script>` 등 → 화면에 그 글자 그대로, 해당 요소 없음), 그다음 고침.
- 결과: `docs/security/2026-11-14-출력-점검표.md`(넣는 곳·값 출처·처리·판단). 이름 바꾸기 화면, 저장 가져오기 검사도 포함.

### 3-3. 흔들리는 시험

- `tests/build_test.py` ~1140-1171: 고정 `wait_for_timeout(500)` 대신 「서비스 작업자가 새 판을 저장했다」는 조건(캐시에 새 판 `index.html`이 있음, 또는 작업자 상태가 `activated`)을 기다림. 바뀐 시험을 20번 연속 돌려 통과.

## 4. 시험

- 배포판 빌드에 외부 주소 없음: `dist/index.html`·`sw.js`·작업자 글에 `cdn.jsdelivr.net`(및 `http`로 시작하는 실행 주소) 없음; 브라우저로 배포판을 열어 파이썬 준비·레슨 코드 실행까지 하는 동안 같은 출처가 아닌 요청 0개.
- 오프라인: 서비스 작업자 설치 뒤 네트워크 끊고 새로 고침 → 파이썬 준비·실행(기존 오프라인 시험 확장).
- 출력 점검에서 고친 곳마다 시험. 기존 전체 묶음 통과. 첫 화면 시간(느린 3G)이 v0.19.0보다 10% 넘게 나빠지지 않음.
