# 경비실 3~17장 사건 45개 + 장별 파일 (v0.16.0) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 경비실 사건을 3~17장 장마다 3개(총 45개)로 늘리고, 사건 본문을 첫 파일에서 장별 JSON 파일로 떼어 낸다.

**Architecture:** 원본은 `data/guard.js` 하나. 빌드가 레슨 장 파일처럼 `guard/chN-<지문>.json`(본문, `solution` 제외)과 첫 파일 속 색인(`window.RIA_GUARD_INDEX`·`RIA_GUARD_FILES`)으로 나눈다. 앱의 목록·등급·배지·저장 다듬기는 색인만 쓰고, 사건 화면은 그 장 파일을 받아서 연다. 개발판은 `src/guard/guarddev.js`가 `data/guard.js`를 직접 불러오고, 배포판에서는 빈 모듈로 바뀐다(레슨 `lessondev.js`와 같은 방식).

**Tech Stack:** 기존 그대로(Pyodide 314.0.7, 바닐라 JS + esbuild, `node --test`, pytest, Playwright). 새 의존성 없음.

**Spec:** `docs/specs/2026-11-13-경비실-사건-12개-설계.md`(제목은 「3~17장 사건 45개」로 갱신됨)

## Global Constraints

- 작업 브랜치는 로컬 `feature/guard-content`. **푸시 금지**, `feature/guard-room`에 합치지 않음(사용자 승인 뒤 컨트롤러가 한다).
- 첫 파일(`dist/index.html`) **844,631바이트 미만**(v0.15.0 최종 크기). 상한 850KB(G-C6)는 그대로.
- 코드 속 이름은 한·영 공통 영어: `attempt`, `password`, `block()`, `allow()`, `has_try()`, `next_try()`, `check`. 시도 값만 언어별로 다를 수 있음(`value_en`).
- 사건 첫 해결에만 XP 5(`GUARD_XP`), 바이트를 직접 주지 않음(G-C2). `saveVer` 2 그대로, `save.garden`은 건드리지 않음.
- 기존 G1~G6의 id·내용·시도는 바꾸지 않는다. 새 사건은 G7~G45, 장 순서는 설계서 §5-3/§5-7.
- 방어 쪽 코드만. 주소는 `.example`만, 인물·업체는 가상. 네트워크(`urlopen`), `sqlite3`, 그래프 모듈은 경비실에서 쓰지 않음.
- 영어 글은 `i18n/en/data.json`의 `guard.<id>.title|brief|ria|concept|crowIntro|crowLose`, `guard.<id>.why.<i>`. 화면 문구는 `t```로, 영어는 `i18n/en/ui.guard.json`.
- 정답 코드는 그 장까지 배운 문법만(설계서 §5-6 표), 내포(comprehension) 금지.
- 사건마다 빈칸 2~3개, 보기 2~3개(첫 보기가 정답), 시도 1~20개, 공격·손님 각각 1개 이상, 경계값 시도 1개 이상.
- `README.md`는 손으로 고치지 않는다(`tools/readme_gen.py`).
- 판정은 `docs/plans/ledger.md`의 「v0.16 경비실 45」 표에 G2-C1, G2-C2 … 번호로 남긴다.
