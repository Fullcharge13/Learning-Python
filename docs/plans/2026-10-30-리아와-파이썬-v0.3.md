# 「리아와 파이썬!」 v0.3 계획서 — 장 따로 불러오기 + 7~10장

**목표**: (1) 레슨 내용을 장 파일로 나눠 첫 화면 파일 크기를 장 수와 상관없게 만든다. (2) 7장 리스트, 8장 딕셔너리, 9장 튜플과 집합, 10장 예외 처리를 더해 레슨을 50개로 늘린다.

**설계서**: `docs/specs/2026-10-30-장-따로-불러오기-설계.md`(확정), `docs/specs/2026-10-30-커리큘럼-4-17장-초안.md`(7~10장 표) · 작성 규칙: `docs/lesson-writing-guide.md`

**전역 제약**: v0.2와 같다(점검기가 기준, Sonnet 초안·Opus 검토, 커밋·배포는 허락 후). 단, 장 파일 작업(작업 1)은 구조 변경이라 Opus가 맡는다.

**검토 중점**
1. 오프라인에서 저장 안 된 장을 열 때 멈추거나 빈 화면 → 작업 1 `test_chapter_blocked_retry`
2. 새 판 배포 뒤 옛 장 파일이 남아 옛 문제가 보임 → 작업 1 `test_chapter_cache_rotation`
3. 복습이 장 파일을 못 받아 실패 → 작업 1 `test_review_lazy`
4. 리스트 장의 별칭(같은 리스트를 두 이름이 가리킴) 설명 정확성 → 작업 4 검토
5. 예외 처리 장에서 learner의 `except:`가 채점 오류를 삼킴 → 채점기는 이미 처리(C18), 작업 6 검토에서 확인

## 작업 2. 점검기 7~10장 표와 개념 (Opus 일꾼, 작업 1과 동시)

**파일**: `tests/content.py`(`CHAPTER_RULES`에 4줄), `data/concepts.js`, `tests/content_rules_test.py`
- 7장: 리스트 리터럴, 리스트 메서드(append, remove, pop, sort, index), `sorted`, `sum`, `list`, 인덱싱으로 바꾸기. 컴프리헨션은 계속 금지
- 8장: 딕셔너리 리터럴, `get`, `keys`, `values`, `items`(튜플은 풀어서만), `in`
- 9장: 튜플 리터럴, 묶고 풀기, 집합 리터럴과 `set`, 교집합·합집합
- 10장: `try/except/else/finally`, `raise`
- 개념 id: `list`, `listmod`, `listloop`, `listfunc`, `dict`, `dictmod`, `dictget`, `count`, `tuple`, `unpack`, `items`, `set`, `exc`, `try`, `excmulti`, `raise`
