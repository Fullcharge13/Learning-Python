# 「경비실」 v0.16.1 다듬기 설계 — 디버깅 시뮬레이션 반영

- 작성일: 2026-11-13 · 상태: **사용자 위임으로 진행**(사용자: 「위 1~6을 v0.16.1로 설계해서 진행」, 지난번처럼 추천안으로 만들고 커밋·푸시는 보고 후 승인)
- 바탕: v0.16.0(`feature/guard-room` `c015eac`), 디버깅 시뮬레이션 보고(페르소나 3 × 한·영 × 3회 = 18회, 2026-11-13)
- 작업 브랜치: 로컬 `feature/guard-hardening`(푸시·합치기는 승인 뒤)

## 1. 의도

시뮬레이션에서 나온 문제를 고쳐, 학습자가 ① 앱이 죽지 않고 ② 감으로는 풀 수 없으며 ③ 틀렸을 때 고칠 방향을 알고 ④ 틀린 방어를 맞다고 믿지 않게 한다.

**하지 않을 것**: 「왜?」를 학습자 코드에 맞춰 바꾸기, 경비실 `print` 출력 칸, 큰 코드 붙여넣기 속도, 하드코딩(시도 값을 그대로 적기) 원천 차단 — 다음 판 이후.

**실패로 볼 것**: 이미 푼 기록·XP가 바뀜, 첫 파일 상한 850KB(G-C6) 초과, 기존 레슨·텃밭 동작 회귀.

## 2. 정한 것 (추천안)

### 2-1. 엔진이 죽지 않게 (시뮬 ①)

- **치명 오류 감지와 재시작**: 작업자(worker)가 Pyodide 치명 오류(메시지에 `fatal`/`already fatally failed`, 또는 `RangeError: Maximum call stack size exceeded`가 Pyodide 밖으로 나옴)를 만나면, 그 실행 결과를 오류 종류 **`EngineCrash`**로 돌려주고 `PyRun`이 작업자를 새로 띄운다(지금의 시간 초과 재시작 길과 같은 `_restart`). 다음 실행은 정상이어야 한다.
- **`EngineCrash` 오류 안내**(data/errors.js + 영어): 「파이썬 엔진이 멈춰서 다시 켰어요. 아주 깊게 겹친 자료나 끝없이 자기를 부르는 함수가 원인일 때가 많아요. 코드를 줄여서 다시 실행해 보세요.」
- **`builtins` 되돌리기**: `runner.run`이 실행 전 `builtins.__dict__`를 복사해 두고, 끝나면(성공·오류 모두) 원래대로 되돌린다(새로 생긴 이름 지우기, 바뀐 이름 원래 값). `builtins.__import__ = None` 같은 조작이 다음 실행에 남지 않는다.

### 2-2. 빈칸 보기 섞기 (시뮬 ②)

- 화면에 보이는 보기 순서를 **사건 id로 정해지는 섞기**로 바꾼다(같은 사건은 늘 같은 순서 — 시험·스크린샷이 안정적). 저장·판정은 지금처럼 **데이터 순서 번호**를 쓴다(화면 번호 ↔ 데이터 번호 변환은 화면에서만).
- 조건: 사건 45개 전체에서 정답이 화면 첫 자리에 오는 빈칸 비율이 **50% 미만**이어야 한다(시험으로 고정). 섞기 함수는 기존 `src/shuffle.js`가 시드 섞기를 지원하면 그것을 쓴다.

### 2-3. 「판정하지 않음」 따로 보기 (시뮬 ③)

- 지금: 아무 명령도 부르지 않은 시도(`none`)는 들임으로 쳐서, 손님 시도는 맞은 것이 된다 → `allow`(괄호 없음)·`pass`·`print(allow)`가 해결됨.
- 바꿈: `none`은 **손님 시도에서도 틀림**(ok=false). 화면 칸은 ⚪ 「판정 안 함」, 「왜?」 앞에 「이 시도에서 allow()도 block()도 부르지 않았어요」. 공격 시도의 `none`은 지금처럼 ❌ 뚫림(설명 문구는 위와 같이).
- **두 번 판정**(`twice`)은 칸에 작은 「2번」 표시와 「왜?」 앞 한 줄 「이 시도에서 판정을 두 번 했어요 — 첫 번째만 셌어요」. ok 판정은 그대로(첫 판정).
- 엔진(`guard.py`의 ok 계산)과 앱(`guardConsistent`)을 함께 바꾼다. 이 규칙 변경 뒤 45개 사건 시험(정답 해결·오답 보기 모두 실패)이 계속 통과해야 한다.

### 2-4. 오류 안내 넓히기 (시뮬 ④)

- **새 오류 종류 안내**(한국어 본문·탐정 본문·영어): `IndexError`, `KeyError`, `AttributeError`, `FileNotFoundError`, `ZeroDivisionError`, `JSONDecodeError`, `RecursionError`. 형식은 기존 표(무슨 오류 → 몇 번째 줄 → 왜 → 고치는 방향, 정답 코드 없음).
- **같은 종류 안 원인별 안내**(메시지 무늬로 고름): 데이터에 `ERROR_VARIANTS = [{ type, pattern, key }]`(첫 일치), `explain()`이 `error.msg`가 무늬와 맞으면 `key` 항목을 쓴다.
  - `TypeError_self`: `takes \d+ positional arguments? but \d+ were given` → 「메서드 정의의 첫 칸 self를 빠뜨렸는지」(15장)
  - `TypeError_compare`: `not supported between instances of` → 「서로 비교할 수 없는 두 값(목록과 집합 등)」
  - `TypeError_container`: `is not (iterable|a container)` / `argument of type 'NoneType'` → 「None이나 숫자 안을 in으로 찾음 — get의 기본값을 확인」
  - `TypeError_call`: `object is not callable` → 「값을 함수처럼 () 로 불렀음」
  - `NameError_import`: `name '(re|json|csv|urlparse|parse_qs)' is not defined` → 「import 줄을 빠뜨렸는지」
  - `NameError_starter`: 정의되지 않은 이름이 그 사건 시작 코드에 있던 이름이면 → 「시작 코드의 줄을 지웠는지」(경비실 화면에서만, 화면이 시작 코드 이름 목록을 넘긴다)
  - `SyntaxError_eq`: 메시지에 `Maybe you meant '=='` → 「= 는 넣기, == 는 비교」
- `GuardAnswerError` 메시지에 실제로 돌려준 값의 종류를 넣는다(「check가 None을 돌려줬어요」, 「… re.Match를 …」, 「… function을 …」 — 괄호 없는 메서드).
- `GuardUsageError`(시도 없는데 `next_try()`) 안내에서 「check 함수 사건이면…」 줄은 그 사건 방식이 func일 때만.

### 2-5. 시도 보강과 보안 정답 보완 (시뮬 ⑤⑥)

원칙: 기존 시도는 순서·`why` 번호를 바꾸지 않고 **뒤에 덧붙인다**. 추가 시도마다 한국어 `why` + 영어 키. 바꾼 정답은 빈칸·시작 코드와 함께 바꾸고, 오답 보기가 여전히 실패해야 한다. 시도는 사건당 20개 이하.

| 사건 | 덧붙일 시도(기대) | 걸러질 틀린 풀이 / 보완 |
|---|---|---|
| G1 | `sunflower77x`🛡, ` sunflower77`🛡 | 앞부분 일치, `strip()` |
| G6 | 정확히 8자이고 규칙을 지킨 손님 ✅ | `len > 8` |
| G7 | `own`🛡, `owner2`🛡, `""`🛡 | 접두·부분 일치 |
| G13 | 목록에 없는 짧은 비밀번호 ✅ | 덧붙인 길이 제한 |
| G16 | `owner:delete:x`🛡, `guest`(콜론 없음)🛡 | **정답 보완**: 나눈 조각이 정확히 2개일 때만 판단 |
| G22 | `²`🛡, ` 5 `는 int가 받으므로 손님 ✅로 명시 | `isdigit()` 검사 |
| G28 | `123456\n`🛡, `١٢٣٤٥٦`🛡 | **정답 보완**: `[0-9]{6}` + `fullmatch`. `$`·`\d` 풀이가 실패 |
| G31 | `https://evilfarm.pi.example/`🛡, `https://evil.example\@farm.pi.example/`🛡, `HTTPS://FARM.PI.EXAMPLE/`✅ | **정답 보완**: 주소에 `\`가 있으면 거부. `endswith` 풀이 실패 |
| G33 | 작은따옴표 `href='//evil.example'`🛡, `src="//evil.example"`🛡 | **정답 보완**: `href`·`src` 둘 다, 큰·작은따옴표 둘 다. 따옴표 없는 속성은 개념 한 줄로만 언급 |
| G40 | `DELETE FROM seeds WHERE id IN (SELECT id FROM x)`🛡 | 포함 검사 `"SELECT" in q` |
| G41 | `SELECT COUNT(*) FROM m; SELECT * FROM members`🛡, `SELECT COUNT(*), tel FROM members`🛡 | **정답 보완**: `;` 거부, 집계 함수 밖의 열 거부(예: `SELECT`와 `FROM` 사이가 `COUNT(…)`/`AVG(…)`만) |
| G43 | 평균이 소수이고 정확히 2배인 값 ✅, 기준선이 4개 넘은 뒤 최근 3개 평균과 전체 평균이 갈리는 값 | `//`, 최근 3개 평균 |
| G44 | `50,51`🛡, `10,-5`🛡 | `round()`. **정답 보완**: 음수 거부 |
| G12 | (시도 없음) | **카드 문구**: 「코드 조각이 못 들어온다」 과장 고침 → 「이 세 글자를 막는 건 첫 단계예요. 진짜 방어는 출력할 때 바꿔 쓰는 것(이스케이프)」 |
| G34 | (시도 없음) | **안내**: 학습자 코드에 `eval(`이 있으면 해결 창에 한 줄 경고 「eval은 입력을 코드로 실행해요. JSON은 json.loads로 읽어요」(화면에서 코드 문자열 검사) |
| G4·G10 | (시도 없음) | **개념 한 줄**: 계정 잠금은 공격자가 일부러 진짜 사용자를 잠글 수도 있다(그래서 실제로는 시간 잠금·추가 확인을 함께 씀) |

### 2-6. 화면 사소 문제 (시뮬 ⑦)

- 영어판 머리 부제(「Apprentice Gatekeeper · 3/45 …」)가 잘리지 않게 두 줄 허용.
- 실행 뒤 오류 카드가 아래 고정 단추 줄에 가려지지 않게: 오류가 나면 오류 카드 위쪽이 보이도록 스크롤.
- 직접 쓰기 첫 내용(판정 G-C7 바꿈): 저장된 코드가 없으면 **그 사건을 해결한 빈칸 고르기로 채운 코드**(지금은 `___`가 남은 시작 코드).

## 3. 확인 방법 (완료 기준)

- `tests/py/test_guard.py`: `none`이 손님에서도 ok=false, `twice` 유지, `GuardAnswerError` 메시지에 돌려준 값 종류, `builtins` 조작이 다음 `run`에 남지 않음(`builtins.__import__ = None` 뒤 정상 실행).
- `tests/grader_browser.py`: 치명 오류를 내는 코드(깊게 겹친 리스트 출력) → 결과 `EngineCrash`, 바로 다음 실행 정상.
- `tests/unit`: `ERROR_VARIANTS` 무늬별 선택, 새 오류 종류 안내, 보기 섞기(같은 id 같은 순서, 데이터 번호로 저장, 첫 자리 정답 비율 < 50%), `guardConsistent`의 새 `none` 규칙.
- `tests/guard_incidents.py`: 45개 모두 기존 검사 + 위 표의 덧붙인 시도와 정답 보완, 그리고 **표의 「걸러질 틀린 풀이」를 사건별로 실제 실행해 실패하는지**(시험 안에 틀린 풀이 목록).
- `tests/flow.py`: 보기 순서가 섞인 채로 정답 고르기 해결, ⚪ 「판정 안 함」 칸과 문구, `EngineCrash` 뒤 다시 실행, 영어판 머리 부제가 잘리지 않음, 오류 뒤 오류 카드가 화면에 보임, 직접 쓰기 첫 내용에 `___` 없음, G34 `eval` 경고.
- 기존 묶음 회귀 없음, 첫 파일 < 850KB, 경제 시뮬레이션 그대로.
- 마지막에 디버깅 시뮬레이션을 짧게 다시 돌려(페르소나 3 × 한·영 × 1회) 위 항목이 고쳐졌는지 확인한다.
