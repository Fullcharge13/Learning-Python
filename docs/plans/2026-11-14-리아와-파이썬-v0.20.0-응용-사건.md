# 경비실 응용 사건 15개 + 사건 파일 카드 (v0.20.0) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 3~17장마다 응용 사건 1개(G46~G60)를 더하고, 풀면 현실 공격과 이어 주는 「사건 파일」 카드를 보여 준다.

**Architecture:** 응용 사건은 기존 사건 데이터(`data/guard.js`)에 `tier: "field"`와 `file` 카드를 붙인 사건이다. 같은 장 파일·엔진·채점을 그대로 쓴다. 열림·등급·배지는 색인(`tier` 포함)과 저장만으로 판정하고, 카드는 새 화면 조각 `src/ui/guardfile.js`가 그린다.

**Tech Stack:** 바닐라 JS(ES 모듈, esbuild 빌드), Pyodide 위 파이썬 판정 엔진, node:test(`npm test`), pytest, Playwright 흐름 시험(`tests/flow.py`), `tests/guard_incidents.py`.

**Spec:** `docs/specs/2026-11-14-경비실-응용-사건-설계.md`

## Global Constraints

- 화면 이름 「응용 사건」·꼬리표 「응용」, 영어 "Field case"·꼬리표 "Field". 코드 이름 `tier: "field"`, 배지 `guard_files`(「사건 파일 수집가」 / "Case File Collector").
- 사건 id G46~G60, 장 3~17에 하나씩, 각 장의 기본 3개 **바로 뒤**에 놓는다.
- 사건은 그 장까지 배운 문법만: `tests/guard_incidents.py`의 `NODES_BY_CH`·`IMPORTS_BY_CH`·`FROM_NAMES_BY_CH`·`CALLS_BY_CH`·`METHODS_BY_CH`를 **넓히지 않는다**.
- 판정은 시도마다 block/allow, 시도 1~20개, block·allow 각 1개 이상, 영어 값은 `value_en`. 엔진(`src/py/guard.py`) 바꾸지 않음.
- 공격·인물·기관·주소는 가상(`.example` 도메인, 가상 기관명). 실존 서비스 이름을 공격 대상으로 쓰지 않음. 카드는 개념·피해 모습·지키는 법까지만(따라 할 공격 절차 금지), 수치 넣지 않음.
- 첫 해결 XP 5(`GUARD_XP`), 바이트 없음. 저장 형식(`saveVer` 2, `save.guard`) 그대로.
- 등급·「n/45 해결」·`guard_perfect`(그림 `n/n` 포함)는 **기본 사건만** 센다. `guard_first`는 그대로(아무 사건).
- 화면에 넣는 데이터 글은 모두 `esc`.
- 대비 4.5:1(밝게·어둡게) 유지. 첫 파일 상한(`build.py`) 안.
- 영어 글: `guard.<id>.file.attack|real|todo`, `guard.<id>.file.search.<n>`(0부터). `alias`는 번역 열쇠 없음.
