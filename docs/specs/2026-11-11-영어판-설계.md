- 작성일: 2026-11-11 · 상태: **확정**
- 사용자 결정(차례대로): 「언어 선택에 영어도 넣을 수 있을까요? 시작 화면 시작하기 버튼 아래 한국어 / English, 설정에서 홈 화면에 추가 아래 언어 버튼 … 계획을 해 주세요」 → 대상 **A**(해외 영어 학습자, 레슨까지 전부) → 배경 **A**(한국 배경 유지, 낯선 말은 처음에 짧게 설명) → 코드 속 글자 **A**(영어로, 텃밭은 두 언어 작물 이름을 모두 받음) → 처음 언어 **A**(휴대폰 언어 따름) → 만드는 방식 **A**(언어 꾸러미 따로 불러오기) → 공개 **A**(다 될 때까지 개발자 모드에서만) → 「v0.14.0 공개버전 작업까지 추천하는 옵션으로 진행 / 커밋과 푸시 전 보고하여 승인」
- 바탕: 장 따로 불러오기(`docs/specs/2026-10-30-장-따로-불러오기-설계.md`), 개발자 모드(C69~), 첫 파일 상한 800KB(C68)

## 0. 목표와 성공 기준

- 휴대폰 언어가 한국어가 아닌 사람이 처음 열면 영어로 시작하고, 1장부터 17장·심화·매일 도전·텃밭까지 **한글을 한 글자도 만나지 않고**(언어 이름 「한국어」 단추 제외) 끝까지 배울 수 있다.
- 언어를 바꿔도 진도·바이트·의상·텃밭·연속 기록이 그대로다(같은 레슨 id·같은 저장).
- 한국어 사용자의 화면·첫 파일 크기·속도는 지금과 같다(첫 파일 800KB 안).
- 자동 시험이 「영어 문구 빠짐」「영어 레슨과 한국어 레슨의 짝 어긋남」「영어 예제 코드의 실행 결과와 정답 어긋남」을 잡는다.

## 1. 언어 설정

- 저장: `save.settings.lang` = `"ko"` | `"en"`. 없으면(옛 저장) `"ko"`. saveVer 그대로(빈 칸은 기본값, 옛 저장 시험).
- 처음 여는 사람(저장 없음): **공개(v0.14.0) 뒤에는** `navigator.languages`의 첫 언어가 `ko`로 시작하면 한국어, 아니면 English. 공개 전에는 늘 한국어.
- 고르는 곳: 시작 화면 「시작하기」 단추 아래 「한국어 / English」 두 단추(지금 언어에 표시), 설정 「홈 화면에 추가」 아래 「언어」 줄에 같은 두 단추. 바꾸면 그 자리에서 화면을 다시 그린다(새로 고침 없이). 영어 꾸러미를 아직 받지 못했으면(오프라인 첫 전환) 「인터넷에 연결되면 바꿀 수 있어요」 안내하고 한국어 유지.
- 공개 전: 두 곳 모두 **개발자 모드일 때만** 보인다. 상수 `EN_PUBLIC`(v0.14.0에서 `true`).
- `<html lang>`, 홈 화면 앱 이름(manifest)은 v0.14.0에서 언어별로.

## 2. 문구 옮기기 구조 (gettext 방식)

설계 대화의 「한국어 표 / English 표」를 다음처럼 구현한다(사용자 보고 사항): 한국어 문구는 **지금 코드 자리에 그대로 두고 열쇠로 쓴다**. 영어 표만 따로 만든다. 수천 곳의 한국어 문구를 옮기다 생길 실수가 없고, 첫 파일은 지금과 거의 같다.

- `src/i18n.js`
  - `t\`한국어 ${x} 문구\`` (태그 붙은 템플릿): 열쇠 = 고정 글자들을 `{}`로 이은 것(`"한국어 {} 문구"`). 영어면 영어 표에서 찾아 `{}` 자리에 값을 차례로 넣고, 한국어면 원문 그대로. 영어 표에 없으면 원문(한국어)으로 두고 개발판 콘솔에 한 번 알림.
  - `tx(id, field, fallback)`: 데이터 표(배지·의상·퀘스트·대사·개념·오류 설명·텃밭 주문) 번역 찾기. 열쇠 = `표이름.id.칸`(예: `badge.first.name`).
  - `lang()`, `setLang()`, `loadPack(lang)`.
  - 한국어 조사(`josa`)는 한국어일 때만 쓰고, 영어 문구에는 조사 자리가 없다.
- 영어 표 원본: `i18n/en/ui.json`(화면·동작 문구: 한국어 열쇠 → 영어), `i18n/en/data.json`(데이터 표: `표.id.칸` → 영어). 사람이 고치는 원본.
- 빌드: 두 원본을 합쳐 `lang/en-<지문8자>.json` 하나로 낸다(+ 영어 레슨 목록). 첫 파일에는 파일 이름만. 서비스 작업자가 저장본에 넣는다(오프라인).
- 시작할 때: 언어가 en이면 영어 꾸러미를 받은 뒤 첫 화면을 그린다(시작 화면은 이미 「파이썬 준비」를 기다리므로 같이 기다림).

## 3. 레슨

- 영어 레슨 원본: `data/lessons/en/chN.js` — 한국어 `data/lessons/chN.js`와 **같은 모양**(같은 레슨·카드·문제 id와 순서·`type`·`answer` 위치·`chips` 수·`concept`·`task` 채점 규칙 종류). 글자(say·q·options·explain·summary·title·goal)와 코드 속 글자·정답 출력만 영어.
- 빌드: `lessons/en/chN-<지문>.json`, 영어 레슨 목록은 영어 꾸러미 안에. 영어 레슨이 없는 장(공개 전 작업 중)은 한국어 장 파일을 쓰고, 개발자 모드 학습 길에 「EN 준비 중」 표시.
- 매일 도전 틀(TEMPLATES)도 같은 방식으로 영어판.
- 짝 시험(`tests/lesson_parity.py`): 모든 영어 장이 한국어 장과 모양이 같은지, 한글이 없는지(허용 목록: 없음), 영어 예제 코드를 실제로 돌린 출력이 정답(`out`·`expected`)과 같은지(기존 `tests/content.py` 점검기를 영어 파일에도 돌림).

## 4. 번역 원칙 (번역 검토 담당이 지킴)

- 리아의 말투: 다정하고 짧은 존댓말 → 친근한 평어 영어(you/we). 농담은 살리되 한국어 말장난은 영어로 통하는 것으로 바꾼다.
- 한국 배경 유지: 원화(₩, won), gimbap·tteokbokki 등은 처음 나올 때 괄호로 짧게 설명(예: gimbap (Korean rice rolls)). 사람 이름은 로마자(Minji 등).
- 프로그래밍 용어는 표준 영어(variable, loop, list, dictionary…). 화면 단추 이름과 설명 속 이름을 맞춘다(용어 목록 `i18n/en/glossary.md`).
- 코드: 변수 이름은 영어 그대로, 문자열·출력만 영어로. 숫자는 가능하면 그대로(정답 변경 최소).

## 5. 파이썬 쪽 (runner.py)

- `run(..., lang="ko")`: 학습자용 쉬운 오류 설명·채점 안내·텃밭 오류 문구를 언어에 따라. 영어 문구는 runner.py 안 사전(빌드가 주석만 빼므로 크기 영향 작음, 첫 파일 확인).
- 텃밭: 작물 이름 `carrot/potato/tomato`와 `당근/감자/토마토`를 모두 받는다. 엔진 안(창고 칸·사건)은 한국어 열쇠 그대로, 화면 표시만 번역 → 저장·결과 대조(C62) 그대로. `what_here()`·`store()`·`seeds()` 등이 돌려주는 작물 이름은 실행 언어를 따른다(영어 코드가 `if what_here() == "carrot"`로 쓸 수 있게).
- 쪽지: 받는 쪽지 이름·내용이 언어별(`orders.txt` 「carrot 2」, 손글씨 「Ria: 3 carrots please! and 2 tomatoes~」 등), 농장일지는 `farm_log.txt`. 정규식 주문(12장)은 영어 쪽지에 맞는 패턴. 텃밭 노드가 만드는 코드도 언어별 이름을 쓴다.

### 5-1. 텃밭 영어 세부 결정 (v0.13.5, 2026-11-11 — 사용자 「v0.14.0까지 추천 옵션으로 진행」에 따라 추천안으로 정함)

| 무엇 | 한국어(안쪽 열쇠) | 영어 실행·화면 | 왜 |
|---|---|---|---|
| 작물 | 당근·감자·토마토 | carrot·potato·tomato | 받는 것은 두 언어 다, 돌려주는 것은 실행 언어 |
| 방향 | 위·아래·왼쪽·오른쪽 | up·down·left·right | 같음 |
| 빈칸 | 빈칸 | empty | `what_here()` |
| 쪽지 파일 | 주문서.txt · 손글씨주문.txt · 농장일지.txt | orders.txt · handwritten.txt · farm_log.txt | 영어 코드 `open("orders.txt")` |
| 주문서 내용 | 「당근 2」 줄마다 작물 개수 | 「carrot 2」 | 줄 나누기(`crop, n = line.split()`) 그대로 |
| 손글씨 주문 | 「리아: 당근2개 부탁해요!」 작물 뒤 숫자 | 「Ria: 2 carrots, please!」 숫자 뒤 작물 | 영어에서 자연스러운 순서 |
| 정규식 「작물+숫자」 | `(당근|감자|토마토)\s*(\d+)` → `for crop, n in …` | 「숫자+작물」 `(\d+)\s*(carrot|potato|tomato)` → `for n, crop in …` | 「carrots」의 carrot도 찾음(복수형) |

- **안쪽은 한국어 열쇠 그대로**: 저장(창고·성장·노드 값·일지 `농장일지.txt`), 엔진 상태, 실행 결과 사건(작물·방향), 주문 판정. 언어는 「파이썬이 보는 이름(코드·쪽지·되돌림 값)」과 「화면 글자」만 바꾼다 → 언어를 바꿔도 텃밭 진행이 그대로이고 결과 대조(C62)도 그대로.
- **runner**: `farm["lang"]`("ko"·"en"). 영어면 쪽지 파일을 영어 이름으로 놓고, 결과 `files`는 안쪽 이름(`농장일지.txt`)으로 돌려준다. 오류·안내 문구(텃밭·차트·연습 서버)도 언어별. 텃밭 아닌 실행은 `run(…, lang=)`.
- **노드**: 노드에 저장되는 값(작물·방향·쪽지·패턴 id)은 안쪽 열쇠. `codegen(program, { lang })`이 언어별 이름으로 코드를 만든다. 새 노드의 기본 글자(「안녕!」, 「당근 」·「개」 등)는 언어별. 학습자가 쓴 글자는 그대로.
- **주문·성장·오늘의 쪽지 글**: 데이터 번역 표(`garden.order.<id>.title|text`, `garden.upgrade.<id>.label`, 쪽지 글은 언어별 표).
- **시험**: pytest(두 언어 이름·영어 되돌림 값·영어 쪽지 이름·영어 오류 문구), 주문 정답 29개를 영어로도 실제 엔진에서 통과, 영어 텃밭 화면에 한글 없음(flow), 이름 표가 JS·파이썬에서 같은지.

## 7. 시험

- 단위: `t` 열쇠 만들기·값 넣기·없는 열쇠는 원문, `tx`, 언어 저장 기본값·옛 저장, 휴대폰 언어 판정, 공개 전 숨김.
- 문구 빠짐(`tests/i18n_coverage.py`): 코드의 모든 `t\`…\`` 열쇠와 모든 데이터 표 id가 영어 표에 있음, 영어 표에 쓰이지 않는 열쇠 없음, 영어 문구에 한글 없음. 코드에 `t` 없이 남은 한글 화면 문구 찾기(허용 목록 관리).
- 레슨 짝 시험(§3), 텃밭 두 언어(pytest·주문 정답을 영어로도 29/29).
- 화면 순회: 영어로 주요 화면 전부(아이폰 17·갤럭시) 넘침·작은 단추·한글 없음.
- 첫 파일 크기, 옛 저장으로 열기, 언어 바꾼 뒤 진도 그대로.
